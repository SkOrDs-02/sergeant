# Політика безпеки

> **Last touched:** 2026-10-03 by @claude (канали звітів про вразливості після переїзду репозиторію). **Next review:** 2027-01-03.
> **Status:** Active

## Як повідомити про вразливість

Пиши через **GitHub Private Vulnerability Reporting**: <https://github.com/SkOrDs-02/sergeant/security/advisories/new>. Це приватний канал, видимий лише власнику проєкту.

Публічний issue чи pull request для вразливості не відкривай: до виправлення це розкриває її всім. Ті самі контакти віддає `/.well-known/security.txt` вебзастосунку (`app.sergeant.com.ua`) і лендингу (`sergeant.com.ua`).

У звіті напиши: що саме не так, кроки відтворення, який вплив (чиї дані чи дії стають доступні) і URL чи версію, де ти це бачив. Тестуй на власному акаунті; якщо знайшов доступ до чужих даних, зупинись на доказі, що він можливий, і не витягуй самі дані.

## Що в скоупі

- вебзастосунок `app.sergeant.com.ua` і лендинг `sergeant.com.ua`;
- API `api.sergeant.com.ua`;
- код у цьому репозиторії, зокрема мобільні клієнти.

Поза скоупом: сервіси третіх сторін, які ми лише підключаємо (Monobank, PrivatBank, Vercel, Hetzner, постачальники AI-моделей), атаки соціальною інженерією, DoS-навантаження, автоматичні сканери без доведеного впливу.

## Чого чекати у відповідь

Часи реакції та усунення залежать від серйозності за CVSS і зафіксовані в [`docs/governance/security/vulnerability-sla.md`](./docs/governance/security/vulnerability-sla.md): від реакції того ж дня й виправлення чи пом'якшення за 24 години для critical до best-effort і 90 днів для low. Це внутрішні цілі проєкту з одним відповідальним, а не юридичне зобов'язання.

Відомі й свідомі рішення, про які не треба повідомляти повторно, зібрані в [`docs/governance/security/beta-tester-brief.md`](./docs/governance/security/beta-tester-brief.md).

## Запити щодо персональних даних

Звернення суб'єктів даних (доступ, видалення) і юридичні запити описані на сторінках `/legal/privacy` та `/legal/terms` вебзастосунку. Для звітів про вразливості вони не призначені.
