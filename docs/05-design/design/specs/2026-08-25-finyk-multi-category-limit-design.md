# Мульти-категорійний ліміт бюджету (Фінік)

> **Last touched:** 2026-08-25 by Claude. **Next review:** 2027-04-12.
> **Status:** Shipped

## Запит

Тестерка: «А буде можливість декілька категорій в ліміт? Наприклад я хочу на
їду витрати Х грн — Продукти + Кафе/ресторани в сумі». Поточна модель
`LimitBudget` тримала рівно одну категорію (`categoryId`), а ручна таксономія
навмисно розводить `groceries → food` і `cafe → restaurant` у РІЗНІ канонічні
кошики — тобто «їжа разом» недосяжна нічим, крім фічі набору категорій.

## Продуктові рішення (founder, 2026-08-25)

1. **Перекриття категорій між лімітами — дозволити з попередженням.** Форма не
   блокує категорію, що вже входить в інший ліміт, але показує підказку
   «"Кафе" вже є в ліміті "Їжа" — витрати рахуватимуться в обох». Блокується
   лише точний дублікат набору.
2. **Назва комбо — опціональна з авто-fallback-ом:** порожньо → «A + B», при
   3+ категоріях «A + ще N». Поле зʼявляється лише при 2+ категоріях.
3. **Картка комбо — сума + розбивка:** спільний прогрес-бар по загальному
   факту, під ним рядок факту на кожну категорію (без під-лімітів).

## Модель даних

- `LimitBudget.categoryIds?: string[]` поверх legacy `categoryId`.
  `normalizeLimitBudget` добудовує `categoryIds` з `[categoryId]` на read-time
  і тримає `categoryId` = перша категорія набору — старі записи, бекапи,
  mobile-читачі й insights лишаються валідними без міграції даних.
- Бюджети синкаються як JSON-блоб (`finyk_budgets.data_json`), сервер форму не
  інтерпретує — SQL-міграція не потрібна. `BudgetSchema` (zod, read-time
  валідація) отримала `categoryIds` явно.
- Ключ порад/кешів — `limitBudgetCategoryKey` (sorted join «+»): зміна складу
  комбо дає новий ключ і свіжу AI-пораду без ручної інвалідації.

## Арифметика

`calcLimitCategorySpent` / `calcLimitCategoryBreakdown` переїхали в
`@sergeant/finyk-domain/lib/limitCategorySpend` (web-файл — re-export shim).
Обидві працюють через обʼєднання bucket-ів ручної таксономії; транзакція або
частка спліту лягає в перший кошик набору, який її приймає — подвійного
рахунку всередині ліміту немає, сума розбивки = факт комбо.

Спільний рахунок підключено всюди, де ліміт порівнюється з фактом: картка
ліміту (Budgets), алерти Overview (web + mobile), `useBudgetOverrunInsight`,
insights-правила `budgetLimits` / `frequentNoBudget`, список лімітів mobile.
Прогноз (`forecastEngine`) поки одно-категорійний — комбо виключені з
прогнозу на mobile свідомо, до підтримки набору в engine.

## Поверхні

- **AddBudgetForm (web):** чипи обраних категорій + селект «Додай ще
  категорію (необов'язково)», опціональна назва при 2+, попередження про
  перекриття, помилка точного дубліката набору.
- **LimitBudgetCard (web):** до 3 чипів категорій (+N), підпис через
  `formatLimitBudgetLabel`, розбивка по категоріях при 2+.
- **Mobile:** створення комбо поки web-only; відображення (список, алерти,
  edit-sheet) рахує і підписує набір коректно.
- Deep-link `?cat=…` лишається категорійним: комбо-картка реєструється під
  кожним своїм id.
