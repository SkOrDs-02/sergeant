## Що перевіряють нові тести

### Фото: збої браузерних API та ресурси

21 unit-тест додає відсутній `document`, відмову canvas/context/encoder,
порожній blob, обидві відмови `createImageBitmap`, завислий `<img>`, пізні
події після завершення, помилки створення/звільнення object URL, виняток
конструктора `Image`, intrinsic-розміри, вузьке зображення, ім'я файлу та
нормалізацію формату. Decoder/canvas замінені на контрольовані браузерні
межі; перевіряються результат, закриття bitmap, звільнення URL і таймерів.

До виправлення 4 нові тести падали, 17 проходили. Вони відтворили:

- винятки створення canvas/малювання замість обіцяного `null`;
- відкладене до таймауту звільнення object URL і таймера, коли `new Image()`
  кидає виняток.

Тепер помилки canvas повертають `null` із закриттям bitmap, а всі terminal
шляхи `<img>` використовують одне завершення з негайним прибиранням.
Обидва продуктові споживачі вже мали `.catch(() => null)`: це виправлення
контракту helper-а та очищення ресурсів, а не доказ зламаного upload у UI.
Наявні 17 і нові 21 unit-тест разом проходять.

Браузерний сценарій використовує справжній декодер, canvas, JPEG encoder,
форму nutrition та FileReader. SVG 4096×2048 завантажується через file input;
до явного натискання «Зрозуміло» запиту аналізу немає. Після згоди тест
перевіряє JPEG MIME, magic bytes і декодує саме HTTP payload, очікуючи
2048×1024. Лише межа зовнішнього AI-аналізу замінена синтетичною 503-відповіддю;
реальних запитів до AI-провайдера немає. EXIF/GPS цей сценарій не перевіряє.

### Silpo: реальний транспорт замість лише позитивних контрактів

Локальний `node:http` сервер на випадковому loopback-порту приймає запити
справжнього `HttpClient`/`fetch`. Мережевий транспорт та runtime-схеми не
замокані; звернень до Silpo-провайдера немає. 48 нових тестів охоплюють:

- 15 незалежних endpoint-обгорток: відхилення HTTP 200 з хибною схемою;
- ті самі 15 обгорток: скасування після отримання запиту сервером;
- 8 невалідних payload-ів: помилка схеми до будь-якого HTTP-запиту;
- 6 wire-сценаріїв: кодування opaque ID, DELETE/POST body, query-параметри,
  legacy prefix, відсікання зайвих полів і повернення серверної підмножини;
- 3 варіанти OAuth URL;
- HTTP 403 для wipe: збереження `ApiError`, auth-ознаки та request ID.

Кожен cancellation-тест чекає фактичного надходження запиту, потім abort;
це не перевірка лише заздалегідь скасованого signal. Сервер і всі відкриті
з'єднання закриваються після кожного тесту. Продакшн-код Silpo не змінено.
