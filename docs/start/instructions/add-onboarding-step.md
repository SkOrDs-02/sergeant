# Playbook: додавання кроку web-онбордингу

> **Last touched:** 2026-10-19 by @Skords-01. **Next review:** 2027-02-15.
> **Status:** Active
> **Runtime-specific:** no

**Trigger:** «Додай новий крок в онбординг» / зміна першого запуску нового web-користувача / новий FTUX-етап.

## Owner surface

- Primary surface: `apps/web/src/core/app/WelcomeScreen.tsx`
- Coupled surfaces: `WelcomeModulePicker.tsx`, `OnboardingConsentStep.tsx`, `onboardingGate.ts`
- Governing skill: `sergeant-web-ui`

## Поточний шлях

Web-онбординг є коротким послідовним шляхом зі станом:

1. `WelcomeModulePicker` дає вибрати набір модулів.
2. `OnboardingConsentStep` записує рішення про аналітику.
3. `WelcomeScreen.completeOnboarding()` зберігає завершення і веде людину до першої дії в модулі.

Старий рядковий web-компонент `OnboardingWizard` видалено 2026-10-18. Не відновлюй його і не підʼєднуй web-кроки через `ONBOARDING_STEPS`. Цей спільний список лишився для замороженої React Native поверхні й не керує web-шляхом.

Люди, які вже завершили онбординг, зберігають наявну позначку завершення. Новий крок не відкриває онбординг повторно. Окремий шлях ознайомлення для чинних користувачів є іншою продуктовою зміною.

## Кроки

### 1. Визнач межу стану

Додай новий стан у `WelcomeScreen` і явно опиши переходи вперед та назад. Запис завершення має лишитися в `completeOnboarding()`, щоб частково пройдений шлях не позначив онбординг завершеним.

Якщо крок збирає довготривалі дані, використовуй наявне типізоване сховище відповідного домену. Не додавай другий кеш онбордингу для того самого значення.

### 2. Створи крок

Великий повторно вживаний крок розмісти поруч із поточними welcome-компонентами в `apps/web/src/core/app`. Малий одноразовий крок лишай у `WelcomeScreen`, якщо винесення приховає переходи стану.

Використовуй наявні контроли й токени. Крок повинен мати:

- одну чітку мету;
- видиму основну дію;
- робочу дію повернення, коли користувач може піти назад;
- клавіатурний фокус, доступні назви та перекладений видимий текст;
- придатний макет на 390 x 844 у світлій і темній темах.

Не змінюй `apps/mobile` чи `apps/mobile-shell`. React Native лишається замороженим за ADR-0094.

### 3. Збережи семантику завершення

Останній перехід усе ще має:

- один раз зберегти вибраний набір і модулі;
- один раз зберегти згоду;
- один раз позначити онбординг завершеним;
- один раз надіслати аналітичну подію завершення;
- перейти до вибраної першої дії.

Користувачі, які повернулися, мають і далі оминати welcome-шлях.

### 4. Аналітика

Використовуй чинні події онбордингу з `packages/shared/src/lib/analyticsEvents.ts`. Web-шлях передає `preset_picker` як варіант входу. Додавай нову подію лише тоді, коли нову дію користувача неможливо описати наявною подією, і в тому самому PR онови observability-документацію точним payload-контрактом.

### 5. Тести

Перевіряй видимий шлях користувача, а не внутрішню будову компонента:

- новий крок відкривається після попередньої дії;
- переходи вперед і назад зберігають введений стан;
- завершення створює один запис у сховищі та одну аналітичну подію;
- користувачі, які повернулися, не бачать welcome-шлях;
- вибрана перша дія лишається правильною.

Почни з фокусних наборів для `WelcomeScreen`, `WelcomeModulePicker`, нового кроку та `onboardingGate`.
