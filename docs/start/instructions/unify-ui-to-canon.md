# Playbook: Звести дублікати UI до канону і закріпити храповиком

> **Last touched:** 2026-10-09 by @test. **Next review:** 2027-01-12.
> **Status:** Active
> **Runtime-specific:** no

**Trigger:** «одна річ робиться пʼятьма способами» · легасі-API компонента треба зняти · знахідка аудиту уніфікації · копії однієї утиліти дають різні числа · після хвилі зведення треба не дати боргу відрости.

## Owner surface

- Primary surface: `apps/web/src` (примітиви `shared/components/ui`, утиліти `shared/lib`)
- Coupled surface: `scripts/check-ui-canon-ratchet.mjs`, `.tech-debt/ui-canon-budget.json`, `packages/design-tokens`
- Governing skill: `sergeant-web-ui`
- Coupled skill: `sergeant-tech-debt` (коли це саме борг, а не фіча)

## Чому це окремий жанр роботи

Дублікат UI рідко ламається голосно. Найдорожче в ньому те, що всі копії **тихі**: жодна поверхня не сигналить, що порахувала або відмалювала за іншим правилом. Тому робота складається з двох половин, і друга обовʼязкова:

1. **Звести** копії до канону.
2. **Закріпити храповиком**, інакше воно відросте — паралельно з бази, поки твоя гілка жила окремо.

Без другої половини хвиля не закінчена. Реальний випадок: 11 кнопок приїхали з `main` у канонічно зведений код рівно тому, що на момент хвилі гейта ще не було.

## Steps

### 1. Заміряти дрейф, не оцінити його

Порахуй **усі** форми, якими сьогодні роблять одну річ, із числами. Число вирішує, що є каноном:

```bash
node scripts/check-ui-canon-ratchet.mjs          # поточні метрики
rg -n --stats 'focus-visible:ring-focus' apps/web/src   # для нової, ще не покритої форми
```

Приклад із фокус-кільця: один токен писали **сімома** рівнями непрозорості — `/45` у 124 місцях, без суфікса 21, `/60` 14, `/30` 12, `/50` 5, `/40` 2, `/25` 1. Канон обрано заміром: 124 проти 21 у наступного, тобто це не новий стандарт для розкату, а **де-факто чинний**.

> **Grep має сліпі зони.** Один файл містив сирий байт NUL у літералі, через що `grep`/`rg` вважали його бінарним і пропускали ЦІЛКОМ. Знайшовся лише тому, що храповик читає файли напряму. Для фінального заміру довіряй скрипту, не греп-конвеєру.

### 2. Обрати канон і зробити міграцію байт-ідентичною

Найдешевша міграція — та, що не змінює вивід. Для цього канонічний API має **резолвитись вниз** до тієї ж реалізації, що й легасі.

Так зроблено в `Button`: єдине джерело стилю — плоска мапа варіантів, а і канонічний `(variant, tone)`, і застарілий `module` резолвляться до одного з її ключів. Саме це дозволило прогнати codemod на 255 тегах без візуальних змін.

Розділяй у комітах **«рефакторинг без зміни виводу»** і **«видима зміна»**. У хвилі дат на 7 call-site-ів була рівно одна видима зміна, і вона названа в тілі коміту.

### 3. Перевіряти еквівалентність прогоном, а не оком

Дві форми, які «очевидно однакові», регулярно не однакові:

- `{day, month:"short", hour, minute}` через `Intl` → `13 вер., 14:30`, а конкатенація двох хелперів → `13 вер. 14:30`. **`Intl` ставить кому, конкатенація ні.**
- `dateStyle: "medium"` **дійсно** дорівнює `{day:"numeric", month:"short", year:"numeric"}` — але це перевірено прогоном, а не прийнято на віру.

Де еквівалентність важлива — закріпи тестом, який упаде, якщо вона зникне (тоді функція стає дублем і її треба прибрати).

### 4. Не забути про затінення й локальні копії

Дві пастки, що вже спрацьовували:

- **Локальна функція з канонічним іменем.** Файл мав власний `formatDateShort` із іншою семантикою — канонічний імпорт затінився б нею **мовчки**. Перейменовано.
- **Мок із власною копією шкали.** Тест мокав `Icon` і тримав свою копію токен→піксель. Після переходу компонента на токен тест упав так, ніби це регресія, хоча рендерились ті самі пікселі. Лікування — `importOriginal()` і читання шкали з канону. **Копію канону в мок класти не можна.**

### 5. Завести або розширити метрику храповика

Метрика додається рівно в пʼяти місцях [`check-ui-canon-ratchet.mjs`](../../../scripts/check-ui-canon-ratchet.mjs):

1. **Константа канону** — експортована, щоб тест читав її, а не дублював.
2. **Гілка в скані** — сканувати РІВНО свій тег/токен. Перша версія метрики кнопки дала 203 хибні влучання на чужих компонентах.
3. **Ключ із нулем у зведенні лічильників** — інакше метрика для гейта не існує.
4. **Число в** [`.tech-debt/ui-canon-budget.json`](../../../.tech-debt/ui-canon-budget.json) **+ абзац у `rationale`.** Без ключа гейт падає голосно — раніше `55 > undefined` було `false`, і метрика без запису проходила МОВЧКИ.
5. **Рядок у зведеному виводі + тести**: позитив, негатив на ЧУЖОМУ компоненті, «канон читається з константи», і **break-тест**.

Два числа мають різний сенс, і це навмисно:

| Значення бюджету | Сенс                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| `0`              | **заборона на повернення** — форма зведена повністю                      |
| `N > 0`          | **стеля над боргом** — міграція свідомо поза скоупом, але рости не можна |

Метрики 7-11 (redesign v3) ловлять патерни поза каноном: `hoverMotion` (`hover:`/`active:scale`, `hover:-translate-y`, `hover:shadow-glow`), `enterMotion` (`animate-stagger-in`, `page-enter`, `<StaggerChild`), `glass` (`backdrop-blur*`), `bigRadius` (`rounded-xl|2xl|3xl|full` і сторонні форми; `rounded-full` дозволений лише у файлах `ROUNDED_FULL_ALLOWLIST` у скрипті, причина на кожен запис), `kicker` (проп `eyebrow` на `<SectionHeading`). CSS не скануються. Нові ключі гейт без baseline не приймає (exit 1): стартове число впиши в JSON руками разом з абзацом у `rationale`, `--update` лише знижує.

### 6. Оновити baseline і журнал

```bash
node scripts/check-ui-canon-ratchet.mjs --update
```

Храповик ходить **тільки вниз**: якщо будь-яка метрика вища за baseline, скрипт відмовляється писати файл. `rationale` автоматично не оновлюється — **правь його руками в тому ж коміті**: звідки замір, чому число таке, що виправлялось у самому гейті.

### 7. Парсерна гігієна гейта — де гейт бреше

Гейт, що міряє неправильно, гірший за відсутній. Три правила, кожне куплене помилкою:

- **Маскуй рядки лише там, де це доречно.** Для метрики фокус-класів маска рядкових літералів обвалила замір 235 → 7, і гейт лишився зеленим. Там треба гасити **тільки коментарі**.
- **Рахуй чесний кінець тега**, а не `[^>]*`: наївний регекс обривається на `() =>` всередині пропа і **недораховує** (grep дав 260, чесний розбір — 329).
- **Виключай визначення від call-site-ів.** Метрика непрозорості спершу рахувала CSS-визначення утиліти як порушення; `.css` виключено, бо там утиліта навмисно має інше значення для іншої ролі.

## Коли канон і код розходяться — правий не гейт

Окремий випадок, який легко вирішити неправильно. Докстрінг `Input` заявляв «дзеркалить `ring-focus/45`», код стояв на `/30`; докстрінг `Select` суперечив сам собі. Гейт упав.

**Правильна відповідь була не «послабити гейт», а звести код до того, що файли про себе писали.** Дрейф — це не новий стандарт лише тому, що його багато; але й гейт не привід переписати канон під фактичний безлад. Вирішує замір (крок 1) плюс те, що система про себе декларує.

## Родина храповиків

Форма одна на весь репо: `.tech-debt/*-budget.json` — `ui-canon`, `dead-doc-links`, `duplicated-app-logic`, `env-single-source`, `inline-error-responses`, `localstorage-allowlist`; плюс кореневі `coverage-ratchet.json`, `mutation-ratchet.json`, `vi-mock-baseline.json`, `eslint.baseline.js`. Додаєш свій — тримайся тієї ж форми (`budgets` + `rationale`).

Аргумент на користь форми: борг мертвих посилань упав 469 → 468 **без окремого проєкту** — просто тому, що PR, який чіпав ті файли, заодно їх полагодив.

## Метод аудиту, коли дублікатів багато

Коли це не одна форма, а системна проблема — методологія з аудиту уніфікації:

1. **Дедуп самих знахідок** перед кодом: одна операція, названа кількома сканерами, — це одна знахідка (79 сирих → 68).
2. **Класифікація за наслідком**, не за модулем: (1) ламається зараз — копії дають РІЗНІ числа; (2) зводиться механічно — виходи тотожні; (3) **лишаємо як є** — свідома локальність.
3. Секція «лишаємо як є» існує явно, **щоб наступний аудит не «полагодив» те, що вже вирішено**. Записуй і негативний результат («перевірено, чисто») — щоб не пересканували.
4. Формат знахідки: усі копії `file:line` → **Канон** → **«Розходяться на:»** конкретний названий вхід → **«Що бачить користувач:»** → **«Куди зводити:»** з названим блокером.
5. Перезамір через час: вибірка не дає права заявляти пропорцію по всьому документу — вона доводить лише, що документ застарів. **Перед тим як брати звідти задачу, перевір її на поточній голові.**
