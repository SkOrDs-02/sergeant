# Playbook: Звірити твердження лендінга з кодом (дрейф «сайт ↔ код»)

> **Last touched:** 2026-09-28 by @Skords-01. **Next review:** 2026-12-31.
> **Status:** Active
> **Runtime-specific:** no

**Trigger:** «чи сайт ще правду каже» · змінилась поведінка продукту, яку сайт описує · сторінка обіцяє приватність, ліміт чи фічу · періодична ревізія лендінга перед запуском чи після хвилі фіч.

## Owner surface

- Primary surface: `apps/landing/src` (сторінки, `content/`, `lib/routeMeta.json`)
- Coupled surface: `apps/server/src`, `packages/shared/src/data`, `docs/product/modules/**` (джерела істини)
- Governing skill: `sergeant-web-ui`
- Coupled skill: `sergeant-copy-and-tone` (формулювання), `sergeant-security-audit` (твердження про приватність)

---

## Що саме перевіряється

**Не дати.** Дати на сайті зелені механічно: `lastmod` живе в реєстрі маршрутів, видима дата йде з того самого поля, що й sitemap і `dateModified`, а форматер кидає на невалідному вході. Перевіряються **твердження** — кожна фактична заява сторінки проти коду, який вона описує.

Головний урок, який робить цей playbook потрібним:

> **Гейт, який звіряє два описи один з одним, не є гейтом проти дрейфу від реальності — зеленим він буде рівно доти, доки обидва описи помиляються однаково.**

Саме тому всі наявні гейти лендінга (реєстр↔реєстр, сторінка↔сторінка, CSS↔токени) не ловлять цей клас: **жоден із них не звіряє твердження з кодом**.

---

## Steps

### 1. Скласти перелік тверджень

Пройди сторінки й випиши кожну **фактичну** заяву: число, межу, обіцянку, назву механіки. Маркетингова емоція — не твердження; «пʼять запитів на день», «дані не передаються третім сторонам», «426 продуктів у базі» — твердження.

Ділити роботу зручно за поверхнями продукту (Фінік / Харчування / Рутина+Фізрук / AI-шар / приватність і експорт) — так робився аудит 2026-09-14, пʼятьма паралельними проходами.

### 2. Звірити кожне з кодом — джерела істини

| Клас твердження                  | Що відкривати                                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Маршрутизація AI, «хто обробляє» | `apps/server/src/env/chatModels.ts`, `apps/server/src/env/aiRoutingEnv.ts`, `modules/chat/aiQuotaTierModels.ts`, `lib/groq.ts`       |
| «Дані не передаються третім»     | ті самі + `docs/governance/security/llm-subprocessors.md` + гейт периметра `apps/server/src/lib/llmRedactionCoverage.test.ts`        |
| Ліміт Free / платний план        | `packages/shared/src/billing/entitlements.ts` (реєстр доступу; число — рішення ADR; змінюється новим ADR, не правкою)                |
| Експорт і право на дані          | `apps/server/src/modules/me/dataRights.ts`, `apps/web/src/core/settings/DataExportSection.tsx`, `apps/web/src/core/hub/hubBackup.ts` |
| Корпус продуктів Харчування      | `packages/shared/src/data/genericFoods.ts` + канон `docs/product/modules/nutrition.md`                                               |
| Pro-гейти на фічах               | рядок фічі в `entitlements.ts` + `requireFeature(...)` / `requirePlan(...)` на відповідному роуті                                    |
| Продуктова механіка модуля       | `docs/product/modules/<module>.md` — канон; розбіжність код ↔ канон сама по собі знахідка                                            |

**Числа перераховуй руками.** В аудиті корпус базових продуктів рахували по файлу, дефолти маршрутизації читали в схемі env, контрасти рахували за WCAG — жодне число не прийнято на віру.

### 3. Класифікувати знахідку

Три бакети, і перший найдорожчий:

| Клас                              | Чому так                                        |
| --------------------------------- | ----------------------------------------------- |
| **(а) сайт обіцяє більше, ніж є** | найдорожче: продукт продає чесність             |
| **(б) сайт відстав**              | код уже вміє більше, сторінка применшує продукт |
| **(в) формулювання неточне**      | по суті вірно, у деталі ні                      |

**Стандарт доказу: `файл:рядок` з ОБОХ боків** — сторінка і код. Знахідка без другого боку не знахідка.

Класична пара з аудиту 2026-09-14: `/vyhid` обіцяв, що дані «не передаються третім сторонам… без застережень», тоді як чат за замовчуванням іде через шлюз-посередник. Дзеркально — сторінка «чесних меж» перелічувала межі, яких код уже не має, і применшувала продукт рівно там, де читач шукає підтвердження чесності.

### 4. Правити — і зсувати `lastmod` тільки там, де змінився видимий текст

`lastmod` не косметика: він їде в sitemap і в `dateModified` JSON-LD. Зсув без зміни тексту — це брехня про свіжість. Константа статусу на сторінці стану оновлюється разом (це вже закріплено тестом).

### 5. Закрити клас гейтом, а не лише правкою

Правка живе до наступної зміни коду. Гейт живе далі. **Дешевий гейт від дрейфу — тест, що звіряє число на сторінці з числом у коді.**

Перші два кандидати, названі самим аудитом:

- число корпусу `genericFoods.ts` ↔ сторінка Харчування (наявний тест перевіряє лише «більше за 300» — тобто фактичне число не тримає ніщо);
- free-ліміт у реєстрі `entitlements.ts` ↔ сторінка AI-помічника (та сама форма).

Зразок для написання — реєстровий гейт маршрутів і гейт консистентності копірайту в `apps/landing/src`: обидва вже парсять реальні джерела, бракує лише ребра «сайт ↔ код».

## Наявні гейти лендінга — що вони ловлять і чого не ловлять

| Гейт                                 | Ловить                                                                                         | Сліпа зона                    |
| ------------------------------------ | ---------------------------------------------------------------------------------------------- | ----------------------------- |
| реєстр маршрутів                     | розбіжність роутера ↔ мета ↔ `llms.txt`, межі довжини `title`/`description`                    | нічого про правдивість тексту |
| консистентність копірайту            | одне джерело для обіцянок експорту й непродажу, узгодженість строків, дата статусу ↔ `lastmod` | **звіряє сторінки між собою** |
| дрейф токенів                        | CSS лендінга ↔ `packages/design-tokens`                                                        | лише візуал                   |
| `Landing quality (axe + Lighthouse)` | a11y по всіх маршрутах + перф-бюджети                                                          | лише якість, не факти         |

**Одне джерело для обіцянки — половина справи.** Константи в `apps/landing/src/content/` (обіцянка експорту, обіцянка непродажу, шкала впевненості, FAQ, автор) означають, що правка їде на всі сторінки синхронно. Але так само синхронно їде й **помилка** — саме так прожила неправда про експорт.

## Деплой і якість лендінга — чого немає в інших playbook-ах

- CI-джоба `Landing quality (axe + Lighthouse)` міряє **пререндерений `dist/`**, не dev-сервер; крок Lighthouse стоїть під `always()`, щоб падіння axe не ховало число.
- Деплой іде через Actions + Vercel CLI (`deploy-landing.yml`), бо Git-інтеграція Vercel відвалилась і **прод тихо стояв на старій збірці, а в репо нічого про це не сигналізувало**.
- Усі команди деплою йдуть **з кореня репо**: Root Directory проєкту CLI додає сам, і з `cwd=apps/landing` шлях подвоювався.
- Два пост-деплойні гейти: деплой віддає пререндерений HTML (canonical + непорожній корінь) і прод-домен показує саме цю збірку (звірка імені хешованого бандла).
- `apps/landing/vercel.json` — **другий** `vercel.json` у репо поруч із канонічним вебовим; не плутай їх, коли читаєш [`deploy-config-change.md`](./deploy-config-change.md).

## Коли НЕ використовувати цей playbook

- Дрейф **внутрішньої документації**, а не сайту — [`reconcile-doc-drift.md`](./reconcile-doc-drift.md).
- Розбіжність код ↔ продуктовий канон модуля — [`deep-module-audit.md`](./deep-module-audit.md) і канон у `docs/product/modules/`.
- Нова сторінка в застосунку (не на лендінгу) — [`add-new-page-route.md`](./add-new-page-route.md).
- Зміна самої обіцянки продукту, а не її опису — це рішення власника, не правка тексту.
