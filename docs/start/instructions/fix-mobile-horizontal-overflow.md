# Playbook: Поле або блок ширші за екран (горизонтальний overflow)

> **Last touched:** 2026-09-19 by @claude. **Next review:** 2026-12-21.
> **Status:** Active
> **Runtime-specific:** no

**Trigger:** контент їде вбік або обрізаний на вузькому екрані — «форма виїжджає», «сторінку можна посунути вправо», «інпут дати налазить на сусіднє»; або червоний `Mobile UI audit` на `horizontal overflow (px)` чи `content clipped`.

## Owner surface

- Coupled surface: `apps/web/tests/mobile` (гейт), `apps/mobile/src` (той самий клас багів у RN)
- Governing skill: `sergeant-web-ui`

## 0. Спершу: який це з двох дефектів

Їх два, і вони **не одне й те саме**. Плутанина тут коштує найдорожче, бо перший вимірюється очима, а другий — ні.

| Симптом                                                               | Що це                                                                  | Чим ловиться                                                   |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------- |
| Сторінка їздить вбік, видно смугу прокрутки                           | Контент ширший за viewport                                             | `documentElement.scrollWidth - innerWidth`                     |
| Сторінка НЕ їздить, але контент обрізано і до нього ніяк не дістатись | Контент ширший за бокс із `overflow-x: hidden` — той зʼїв би прокрутку | `scrollWidth > clientWidth` на кожному боксі з hidden-overflow |

Другий випадок дає першій перевірці **чистий нуль** — саме так комора проїхала 155px за 393px-екран непоміченою ([PR #925](https://github.com/SkOrDs-02/sergeant/pull/925)). Обидві перевірки живуть в [`apps/web/tests/mobile/audit.ts`](../../../apps/web/tests/mobile/audit.ts) → `auditPage`.

## 1. Відтворити й заміряти, а не вгадувати

```bash
pnpm --filter @sergeant/web e2e:mobile          # блокуючий PR-гейт, coarse pointer
```

Спек ходить по списку `ROUTES` у [`mobile-ui-audit.spec.ts`](../../../apps/web/tests/mobile/mobile-ui-audit.spec.ts). **Твоєї поверхні там може не бути**, і це найчастіша причина, чому баг доїхав до людини: гейт зелений не тому, що все добре, а тому, що рядок, який розпирає трек, у steady-state не рендериться взагалі (порожня комора, згорнутий аркуш, форма за кнопкою). Тоді:

- сценарій із наповненим станом додається окремим тестом поза `ROUTES` (як `PANTRY` у тому ж файлі), або
- для поля всередині аркуша — пін у юніт-тесті на спільний примітив (як `LogPastWorkoutSheet.test.tsx`).

Ручний замір у DevTools на 393px, коли треба точний винуватець:

```js
// хто саме вилазить за viewport
[...document.querySelectorAll("*")].filter(
  (el) => el.getBoundingClientRect().right > innerWidth + 1,
);
// хто обрізаний власним hidden-overflow (другий дефект)
[...document.querySelectorAll("*")].filter(
  (el) =>
    getComputedStyle(el).overflowX === "hidden" &&
    el.scrollWidth - el.clientWidth > 1,
);
```

> Міряй **бокс-кліпер**, а не rect-и дітей. Бокс із hidden-overflow лишається програмно скрольним, браузер його скролить (досить фокуса в полі) — і rect-и дітей ховаються назад у viewport, тобто дефект зникає рівно з того заміру, яким ти його шукаєш.

## 2. Класифікувати причину

| Причина                                                                    | Як упізнати                                                  | Лікування                                                           |
| -------------------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------- |
| **Нативний контрол з intrinsic-шириною** (`input[type=date]`, `type=time`) | Вилазить саме поле дати/часу; на iOS помітніше, ніж у Chrome | `DateField` / `TimeField` замість сирого `Input` — див. § 3         |
| **flex/grid-комірка з дефолтним `min-width: auto`**                        | Батько — `flex` або `grid`, дитина широка й не стискається   | `min-w-0` на комірці (і на всіх проміжних обгортках до неї)         |
| **Довгий нерозривний рядок** (назва з чека, email, URL)                    | Одна довга «стіна» тексту в рядку таблиці/картки             | `min-w-0` + `truncate` або `break-words` на контейнері тексту       |
| **Фіксована ширина в px**                                                  | `w-[360px]`, `min-w-[420px]` у className                     | Замінити на `w-full max-w-[…]`                                      |
| **Горизонтальна стрічка без власного скролу**                              | Ряд чіпів/табів ширший за екран                              | `flex overflow-x-auto no-scrollbar` + `-mx-N px-N` на самій стрічці |

## 3. Канонічний фікс для полів дати й часу

Це найчастіший випадок у цьому репо, і його вже лікували щонайменше тричі (форми Фініка, `LogPastWorkoutSheet` — скарга тестера 2026-08-16, review-екран чек-скану — бета-фідбек №2, 2026-08-18).

**Причина.** У нативного `input[type=date]` є власний intrinsic inline-size від UA-стилів. Комірка flex/grid із дефолтним `min-width: auto` слухняно під нього розширюється, і `w-full` тут не допомагає — він задає бажану ширину, а не мінімальну.

**Chromium цього НЕ відтворює — заміряно 2026-09-15.** Той самий аркуш із сирим `<Input type="date" className="w-full">` проходить `e2e:mobile` (Pixel 5 / Chromium) з нульовим overflow: intrinsic inline-size дає саме WebKit. Отже **playwright-лейн цей клас багів не ловить**, і зелений прогін тут нічого не доводить. Пін мусить бути юніт-тестом на класовий контракт спільного примітива:

```tsx
expect(screen.getByLabelText("Дата").className).toContain(
  "[min-inline-size:0]",
);
```

Він падає на сирому `Input` і проходить на `DateField` (перевірено обома прогонами). Такі піни вже стоять у `LogPastWorkoutSheet.test.tsx` і `ManualExpenseSheet.extra.test.tsx`.

**Не пиши контракт руками.** Використай спільні примітиви — [`DateField`](../../../apps/web/src/shared/components/ui/DateField.tsx) або [`TimeField`](../../../apps/web/src/shared/components/ui/TimeField.tsx). Вони вже несуть `min-w-0` + `max-w-full` + явний `[inline-size:100%]`, плюс межі календаря і читабельний empty-state, якого нативний контрол на iOS не дає.

```tsx
// BAD — сирий контрол, комірка розʼїдеться під його intrinsic-ширину
<Input id={dateId} type="date" className="w-full" {...register("date")} />

// GOOD
<DateField id={dateId} value={date} {...register("date")} />
```

**Третя пастка — ширина треку залежить від локалі ПРИСТРОЮ.** Коли гасиш intrinsic-розпирання фіксованим треком (`w-[9rem]`, `grid-cols-[…_7rem]`), ти забираєш у контрола право бути таким завширшки, як йому треба, — і надто вузький трек його обрізає. Нативний `input[type=time]` рендериться під локаль **пристрою**, не застосунку: `08:30` в uk-UA, але `08:30 AM` в en-US, і це **142px проти 110px** (замір у Chromium 2026-09-15). Клади трек від ширшого варіанта, інакше полагодиш overflow українцям і зламаєш поле тим, у кого телефон англійською. Найдешевший замір — відрендерити контрол без обмежень поруч і зняти його `getBoundingClientRect().width`.

Дві пастки при переході:

1. **`aria-label` перебиває зовнішній `<Label htmlFor>`.** `DateField` завжди ставить собі доступне імʼя (`ariaLabel ?? label ?? emptyLabel`), тож якщо мітка секції стоїть окремо — передай `aria-label` явно, інакше поле назветься службовим «Обери дату» і тести на `getByLabelText` зламаються.
2. **`bounded`.** Типово `DateField` сам класифікує межі й малює свій helper. Якщо форма вже рахує власні помилку й попередження — став `bounded={false}` + явні `min`/`max`, інакше отримаєш два повідомлення про одне й те саме.

## 4. Перевірити фікс

```bash
pnpm --filter @sergeant/db-schema build         # передумова vitest у apps/web
pnpm --filter @sergeant/web test <файли>
pnpm --filter @sergeant/web e2e:mobile          # обидві overflow-перевірки
```

**Спершу переконайся, що твій гейт ловить САМЕ цей баг.** Поверни дефект на хвилину, прожени перевірку, побач червоне — і лише тоді фіксуй. Без цього кроку легко закінчити зеленим гейтом, який був би зеленим і без фікса: так сталося з playwright-лейном для полів дати (§ 3).

## 5. Занотувати, щоб не лікувати вчетверте

Якщо причина виявилась новою для репо — додай рядок у таблицю § 2. Якщо це був нативний контрол — переконайся, що виправлено через спільний примітив, а не локальним `min-w-0` у className: локальний фікс не переносить знання на наступне поле, і саме тому цей баг повертався.

## Verification

Гейт вважається закритим, коли:

- [ ] перевірка **падала** до фікса і проходить після (доведено прогоном, не міркуванням);
- [ ] `horizontal overflow (px)` ≤ 1 **і** `content clipped by an overflow-x:hidden box` порожній;
- [ ] сценарій із НАПОВНЕНИМ станом покритий (не лише steady-state, див. § 1);
- [ ] 44px-флор не зламано супутньою зміною розмірів;
- [ ] у PR є скріншот на 393px (вимога `AGENTS.md § Verification before PR` для UI-змін).
