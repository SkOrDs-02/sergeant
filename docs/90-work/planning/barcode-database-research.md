# Дослідження: бази баркодів для харчових продуктів (фокус — Україна)

> **Last touched:** 2026-08-02 by @Skords-01. **Next review:** 2027-11-09.
> **Status:** Active

Дослідження для nutrition-модуля Sergeant: як апки-конкуренти вирішують проблему «баркод → продукт з КБЖВ», які бази/API існують, покриття українських товарів, ціни. Контекст: у web-апці вже є сканер на `@zxing`.

Методологія: deep-research workflow (105 агентів, adversarial verification 3-vote) + 3 цільові агенти по прайсингу і Україні + прямий запит до Open Food Facts API. Дата зрізу: 2026-08-01.

## TL;DR

1. **Готової бази з добрим покриттям українських продуктів не існує.** Open Food Facts (OFF) — єдина відкрита база — має лише **6 992 продукти з тегом Ukraine** із ~4,66 млн загалом (~0,15%). Комерційні API — US-центричні; жоден не заявляє покриття України явно.
2. **GS1 Ukraine — не джерело даних.** GEPIR повертає лише власника GTIN (компанію), без назви товару чи нутрієнтів. Внутрішній «Депозитарій» GTIN-каталог — members-only для виробників. Public product-data API немає.
3. **Усі успішні апки в цій ніші вирішують проблему однаково — crowdsourcing.** OFF-модель: скан → фото етикетки → OCR/AI-екстракція таблиці КБЖВ (Robotoff: Google Cloud Vision + натренована модель) → підтвердження користувачем/спільнотою. Українські апки (Foodstr ~300k SKU, Таблиця Калорійності) будували власні бази руками + user submissions.
4. **Рекомендована стратегія для Sergeant:** OFF як безкоштовний перший рівень lookup + власна БД user-added продуктів + фото/OCR fallback. Обережно з ODbL share-alike ліцензією при змішуванні даних.

## 1. Відкриті бази

### Open Food Facts — головний кандидат

- ~4,66 млн продуктів, 182+ країни, crowdsourced з 2012 (верифіковано, unanimous votes).
- **Безкоштовний REST API без автентифікації** (обов'язковий лише User-Agent) + повні bulk-експорти: MongoDB dump, JSONL, Parquet (Hugging Face), CSV, RDF ([world.openfoodfacts.org/data](https://world.openfoodfacts.org/data)).
- **Покриття України: 6 992 продукти** (прямий запит `GET /api/v2/search?countries_tags_en=ukraine`, 2026-08-01). Це мало — але тег `countries` ставиться крауд-даними, реальних українських EAN у базі може бути трохи більше без тега.
- Ліцензія: **ODbL 1.0** (структура) + DbCL (контент) + CC BY-SA (фото). **Share-alike**: похідна база, що змішує OFF з іншими даними, має бути відкрита. Практичний обхід, який використовують комерційні апки (Yuka): тримати OFF-дані в окремому шарі/таблиці, не змішуючи зі своєю пропрієтарною базою, + атрибуція.
- Без гарантій якості: власні terms кажуть «no assurances that the data is accurate».
- Fallback-модель OFF (можна скопіювати як UX-патерн): скан → фото етикетки → **Robotoff** (OCR: Google Cloud Vision + модель екстракції nutrition-таблиці) → людське підтвердження + гейміфікація дозаповнення («Hunger Games»).

### USDA FoodData Central

Безкоштовна, якісна, але **тільки US-продукти** (branded foods з GTIN US-ринку). Для України — лише як джерело generic-продуктів (сирі інгредієнти, не брендовані товари).

### GS1 Ukraine

- **GEPIR** ([gepir.gs1ua.org](https://gepir.gs1ua.org/en/search/gtin)) — безкоштовний, але повертає **лише компанію-власника GTIN** (назва юрособи, GLN). Нуль продуктових атрибутів.
- **«Депозитарій»** — електронний каталог GTIN-13, доступ лише членам асоціації (платне членство виробника). Не для third-party апок.
- Глобальний GS1 GDSN — B2B data-pool між торговими партнерами, не публічний API. Для масштабу: GS1 US Data Hub API коштує $6 500 flat (US-ціна; в Україні еквівалента немає).
- Членство gs1ua.org: вступний + річний внески, суми не публікуються (окрема додаткова угода); неофіційне джерело називає ~$50 вступ + $50/рік для ФОП (неверифіковано).
- «Verified by GS1» поступово додає продуктові атрибути, але станом на зараз як джерело нутрієнтів непридатний.

## 3. Як це вирішують конкуренти

- **Yuka** — повністю на OFF + внески власних користувачів (скан невідомого товару → користувач фотографує → дані йдуть і в OFF). Ефективне покриття України обмежене тими ж ~7k продуктами.
- **MyFitnessPal / Lifesum / Yazio** — власні закриті бази + **немодеровані user-added entries**. Peer-reviewed дослідження (2018, NL): точність скан-матчу 96% (MFP) → 5% (SparkPeople); user-generated дані — головна причина браку якості ([PMC10260744](https://pmc.ncbi.nlm.nih.gov/articles/PMC10260744/)).
- **Українські апки:**
  - **Foodstr** — заявляє власну базу ~300 000 SKU, зібрану з полиць українських магазинів (розробники + crowd).
  - **EatFit** — UA-апка з барекод-сканером, позиціонується як «переважно українські продукти».
  - **Таблиця Калорійності** (tablycjakalorijnosti.com.ua) — крауд-база UA-продуктів (АТБ/Сільпо) з модерованим флоу «додати продукт/баркод».
  - **«Худеем вместе»** (CIS) — дозволяє користувачам **редагувати КБЖВ прив'язане до баркода** — непряме свідчення, що барекод-дані по регіону часто хибні.
- Спільний патерн: **ніхто в регіоні не покладається на зовнішній API** — всі будують власну крауд-базу з fallback «додай продукт вручну».

## 4. Рекомендована стратегія для Sergeant

Триярусний lookup (патерн, перевірений Yuka/OFF/Foodstr):

1. **Tier 1 — власна БД Sergeant** (products таблиця з полем `barcode`): спершу шукаємо у своїй базі — туди потрапляє все, що юзери вже додали/підтвердили. З часом це стає головним активом (у Foodstr так виросло 300k SKU).
2. **Tier 2 — Open Food Facts API** (безкоштовно, без ключа): `GET https://world.openfoodfacts.org/api/v2/product/{barcode}` з власним User-Agent. Хіт → показати превʼю, дати підтвердити/поправити КБЖВ. **Ліцензійно: зберігати OFF-походження в окремому полі/шарі (`source: 'off'`), не змішувати у пропрієтарний датасет, атрибуція в UI.**
3. **Tier 3 — не знайдено:** форма ручного додавання (назва + КБЖВ на 100 г) + опційне фото етикетки. Фото → пізніше OCR (у Sergeant вже є receipt-scan напрямок — див. [receipt-scan.md](./specs/receipt-scan.md); та сама інфраструктура vision-моделі може парсити nutrition-таблицю). Продукт одразу доступний юзеру, у спільну базу — після легкої модерації.

Додатково:

- **Contribute-back в OFF** (опційно, пізніше): OFF має WRITE API — продукти, додані юзерами Sergeant, можна публікувати в OFF. Це і виконує share-alike дух, і росте покриття UA для всіх. Але це продуктове рішення founder-а (дані юзерів → публічна база).
- **Не купувати** комерційні API на старті: жоден не доводить покриття UA. Якщо колись — тестувати FatSecret Premier trial на вибірці реальних українських EAN.
- **Метрика для рішень:** логувати hit-rate по tier-ах (скільки сканів знайдено у своїй БД / в OFF / не знайдено). Це дасть реальні цифри покриття замість оцінок і скаже, коли (і чи) потрібен платний API.

## 5. Емпіричний тест: hit-rate OFF на реальних українських полицях (2026-08-01)

Методика: зібрано 100 реальних EAN продуктів з полиць Novus (Київ) через публічний `stores-api.zakaz.ua` (7 харчових категорій: молочка, овочі-фрукти, м'ясо-риба, снеки, бакалія, напої, випічка), кожен прогнано через `GET world.openfoodfacts.org/api/v2/product/{ean}` з нормалізацією GTIN-14→EAN-13.

| Зріз                           | Знайдено в OFF  | З КБЖВ (nutriments) |
| ------------------------------ | --------------- | ------------------- |
| Всі 100 продуктів              | **25%**         | **20%**             |
| Українські (префікс 482, n=75) | **23%** (17/75) | **16%** (12/75)     |
| Імпортні (n=25)                | 32% (8/25)      | —                   |

**Висновок:** OFF закриває приблизно **кожен 4–5-й скан** на реальній українській полиці, і лише ~кожен 6-й — з готовими КБЖВ. Це підтверджує стратегію: OFF корисний як безкоштовний Tier 2, але ~80% сканів потребуватимуть fallback (власна база + ручне додавання/OCR). Сирі дані тесту: скрипт і `off-hitrate.json` у scratchpad сесії (легко відтворити).

Побічна знахідка (перевірено 2026-08-01): `stores-api.zakaz.ua` (Novus/Metro/Auchan/Varus/EKO/Tavria) — відкритий без автентифікації, і **детальна картка продукту** (`GET /stores/{id}/products/{ean}/`) містить повний блок `nutrition_facts` (energy kcal, protein, fat, saturated, carbohydrates, sugars, salt) + `ingredients`, `producer`, `country`, `weight`, фото. Вибірка з 40 продуктів: **100% мають заповнені nutrition_facts і склад**. Масштаб: ~8 000 харчових SKU лише в одному магазині Novus (7 категорій). Це найякісніше відкрите джерело пар «баркод → КБЖВ» для українського ринку. Легальні межі — див. § 6.

## 6. Як швидко наповнити власну UA-базу

Досліджені шляхи (від найшвидшого/найдешевшого):

1. **Bulk-seed з OFF** (безкоштовно, легально): повний дамп (JSONL/Parquet) → відфільтрувати `countries_tags: ukraine` + 482-префікс → ~7–10k продуктів як стартовий корпус. Ліцензія ODbL: тримати окремим шаром з атрибуцією.
2. **OCR фото етикеток через vision-модель** (основний масштабований канал): дослідження MDPI показало стрибок точності екстракції nutrition-таблиці GPT-4o проти класичного OCR — Jaccard 17,8% → **71,6%** ([mdpi.com/2313-433X/11/8/271](https://www.mdpi.com/2313-433X/11/8/271)). Тобто: юзер сканує невідомий баркод → фотографує етикетку → vision-модель заповнює КБЖВ → юзер підтверджує (~70% полів уже правильні). Це той самий пайплайн, що планувався для receipt-scan. Robotoff від OFF сам по собі недостатньо точний (визнають самі OFF) — краще власний виклик vision-моделі.
3. **Retailer API — головне відкрите джерело «баркод → КБЖВ»**: `stores-api.zakaz.ua` без auth віддає в картці продукту повний `nutrition_facts` + склад + виробника (див. § 5; 100% coverage у вибірці, ~8k SKU/магазин). Сільпо — сторінки за анти-ботом (403), ecom-API вимагає branch-id: парсабельно, але з зусиллям. **Легальна рамка**: самі КБЖВ — факти з етикетки виробника, не об'єкт авторського права; але з 2022-12-01 діють sui generis права на бази даних (ЗУ 2811-IX, 15 років захисту від extraction/re-utilization _substantial part_) — тому:
   - **point-lookup одного EAN у момент скану** — insubstantial part, по суті те саме, що робить браузер юзера; прийнятний ризик;
   - **bulk-викачка всієї бази** — саме те, від чого закон захищає; реальна цивільно-правова експозиція + ToS;
   - чистий шлях для bulk — **офіційне партнерство/дозвіл zakaz.ua** (у них B2B-орієнтація, кейс «nutrition-апка посилається на ваш каталог і веде трафік» — продавана історія).
4. **Listex.info** (B2B каталог, GS1-linked): API з GTIN/атрибутами/фото по UA-ринку, але **без nutrition facts** у документованій схемі; ціни непублічні (contact sales). Корисний хіба як backbone назв/брендів.
5. **Contribute-back в OFF**: Producers Platform і write-API безкоштовні й відкриті для third-party — зібрані продукти можна публікувати назад (виконує share-alike і росте покриття для всіх).
6. **Ручний data-entry**: орієнтир по ринку — ~~104 грн/год локальний data-entry (~~$7–18/год аутсорс). При ~2–3 хв/продукт (фото → КБЖВ) виходить грубо **3–5 грн/продукт**; 10k топ-SKU ≈ 30–50 тис. грн разово. Точних розцінок «за продукт» на ринку не знайдено — оцінка похідна.
7. **Як робили інші**: Foodstr (300–600k SKU) — щоденні контент-менеджери + user submissions баркодів у підтримку; Таблиця Калорійності — ручний лог засновника + модеровані заявки юзерів. Ніхто не розкриває scraping чи купівлю даних.

**Практичний рецепт для Sergeant:** OFF-дамп як seed (~7k) → OCR-пайплайн на vision-моделі для user-сканів (з підтвердженням) → опційно разовий data-entry-спринт по топ-500 SKU найпопулярніших товарів (хліб/молоко/яйця/напої — покриють левову частку сканів за законом Парето) → hit-rate метрика вирішує, що далі.

## 7. Прогалини дослідження

- Точний список країн FatSecret Premier — лише через sales.
- Hit-rate міряно на одній мережі (Novus, Київ) і топ-30 продуктах категорій; асортимент АТБ/сільських магазинів може дати інші цифри.
- Listex: чи є в них КБЖВ поза документованою схемою і ціни — лише через прямий контакт.
- Nutritionix точні ціни — непублічні.
- Foodstr/EatFit цифри баз — self-reported marketing, незалежно не верифіковані.
