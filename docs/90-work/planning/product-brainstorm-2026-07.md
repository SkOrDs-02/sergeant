| 2.1 | Приватність AI-потоку («не думав» у finyk/hub-coach)              | **Анонімізація перед відправкою**     | Скрабінг чутливого (мерчанти/суми/PII → узагальнення) перед LLM-провайдерами. ## Раунд 3 — монетизація

| #   | Питання                                  | Рішення                                         | Наслідок                                                                                                                                                                                                                                  |
| --- | ---------------------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.1 | Принцип межі Free/Pro                    | **«Ядро безкоштовне, AI — пейвол»**             | Весь ручний функціонал + банк-sync = Free назавжди; все AI-генеративне (чат понад ліміт, фото, дайджест, проактивність, рецепти) = Pro з teaser-ами. Закриває «монетизацію не продумав» ×5. Historical-таблиці 2/5/∞ остаточно архівувати |
| 3.2 | Квота × частота їжі                      | **Фото-лог поза загальною квотою**              | Для Pro щоденні механіки ядра (фото-лог їжі) — безліміт/окремий щедрий ліміт; загальна квота — лише чат/генеративне. Юзер не боїться логувати вечерю                                                                                      |
| 3.3 | Mono-sync × Free                         | **Банк-sync безкоштовний назавжди**             | Webhook-синхронізація — core value і магніт активації; не гейтиться. Узгоджено з 3.1                                                                                                                                                      |
| 3.4 | Нагадування routine (роль + монетизація) | **Додаток, без гейтів; streak-at-risk зробити** | Ратифікувати код (default off, страхування — не ядро); тір-гейти прибрати з GTM; єдине доробити — streak-at-risk push (узгоджений з гнучким стріком і тоном друга)                                                                        |

## Раунд 4 — продуктова структура

| #   | Питання                            | Рішення                                                                                                                                | Наслідок                                                                                                                                                                                                              |
| --- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4.1 | Роль hub                           | **Самостійна поверхня — «мій день»**                                                                                                   | Hub — місце щоденного ритуалу (чекін, пульс дня, інсайти); модулі — для глибини. Закриває «не визначав» hub-coach канону; інвестиції в hub-дашборд легітимні. Узгоджено з routine-рішенням «чекін на hub рівноцінний» |

## Зріз реалізації на 2026-09-05

Таблиця нижче **не переписує рішення раундів** і не перетворює продуктовий
компас на план розробки. Вона лише розділяє «ухвалено» від «є в `main`» —
попередня редакція змішувала ці два стани. «Частково» означає, що код покриває
помітну частину рішення, але не весь його наслідок.

| #   | Стан коду                   | Підтверджене покриття та залишок                                                                                                                                |
| --- | --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1 | Частково                    | Waitlist-інфра є; invite-gate реєстрації ще не увімкнений.                                                                                                      |
| 1.2 | Частково                    | Є v2 push/pull/stream, серверне застосування sync-операцій та клієнтський outbox; повний SoT-cutover і гарантії для анонімного локального світу не завершені.   |
| 1.3 | Частково                    | Web емітить показ сигналу, чотири доменні дії й базові AI-події; немає mobile-паритету та рішення-дашборду на продових даних.                                   |
| 1.4 | Частково                    | Ресьорч виключив платного вендора на старті; Silpo додає OAuth-пошук продуктів, але не EAN-lookup (`lookupSilpoBarcode` повертає `null`).                       |
| 2.1 | Частково                    | `scrubPII` застосовано в ai-memory; chat і digest ще не мають повного pre-LLM scrub.                                                                            |
| 2.2 | Частково                    | Web трекає `ai_advice_shown` / `_reacted`; немає серверного стабільного `advice_id`, mobile-паритету й доведеного advice → доменна дія.                         |
| 2.3 | Дрифт, потрібна ратифікація | У коді три шари: `coach_memory`, pgvector і локальний Memory Bank; рішення про дві пам'яті не можна мовчки вважати виконаним.                                   |
| 2.4 | Частково                    | Wellbeing-мультиплікатор уже впливає на recovery fatigue; окремого журналу розбіжності «движок ↔ wellbeing» і калібрування порогів немає.                       |
| 3.1 | Реалізовано                 | Ліміт Free = 5, Pro = ∞; ручне ядро не гейтиться AI-планом.                                                                                                     |
| 3.2 | Частково                    | Фото-маршрути використовують спільний `requireAiQuota()`, але Pro має ∞, тож нинішній результат для Pro безлімітний; окремої policy-квоти та Free-teaser немає. |
| 3.3 | Реалізовано                 | Pro-гейт прибрано з підключення Monobank і backfill.                                                                                                            |
| 3.4 | Частково                    | Є in-app рекомендація `routine_streak_at_risk` після 21:00; планувальника та outbound push для неї немає.                                                       |
| 4.1 | Реалізовано                 | Hub працює як окрема поверхня «мій день».                                                                                                                       |
| 4.2 | Продуктово відкрите         | Це свідомо не інженерна задача: відповідь має спиратися на дані з 1.3.                                                                                          |
| 4.3 | Частково                    | Web збирає streak exposure/check-in контекст; mobile і dashboard-інтерпретація ще не готові.                                                                    |
| 4.4 | Актуально                   | Свідомі «ні» не змінилися; routine categories/tags лишаються продуктово відкритими.                                                                             |
