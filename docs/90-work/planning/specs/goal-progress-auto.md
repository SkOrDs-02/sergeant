## Проблема

Прогрес цілі накопичення (`GoalBudgetCard`, поле `savedAmount`) зараз оновлюється лише ручним редагуванням числа — без історії, без звʼязку з реальними накопиченнями юзера в банках (jars) Monobank.

## Мета

Прогрес цілі рахується сам: з балансу привʼязаної банки Monobank та/або з логу поповнень. Редаговане поле «Відкладено» зникає.

## Дизайн-рішення (зафіксовані)

1. **Модель прогресу:** `прогрес = баланс привʼязаної банки (якщо є) + сума ручних поповнень`. Обидва джерела співіснують: банка тягнеться з mono, ручні поповнення — для готівки/інших джерел поверх.
2. **Лог поповнень** замість редагованого поля для ВСІХ цілей: кнопка «+ Поповнити» → сума (+ опційна нотатка) → запис в історію `{id, amountUah, date, note?}`; список в картці цілі (згорнутий за замовчуванням), запис можна видалити (помилкове поповнення). Дата — межі доби Europe/Kyiv.
3. **Привʼязка до банки:** у формі цілі (створення і редагування) — дропдаун банок юзера (naming: «Банка Monobank», опція «Без банки»). Використати shared `Select` (патерн з D3-дропдауна категорій). Привʼязку можна зняти/змінити будь-коли. Якщо в банки задана власна ціль (`goal` з mono) — при створенні цілі з банки підставляти її як дефолт суми цілі (юзер може змінити).
4. **Міграція без втрат:** наявний `savedAmount > 0` конвертується в перший запис логу поповнень («Початковий залишок», дата міграції) — прогрес юзера не обнуляється. Поле `savedAmount` після міграції не редагується з UI (можна лишити в типі як deprecated для сумісності снапшотів — вирішує виконавець, задокументувати).
5. **Свіжість банки:** баланс банки оновлюється щонайменше при кожному звичайному mono-синку/відкритті Фініка. Окремого realtime не потрібно.

## Поверхня (перевірено на main 2026-07-26)

**Server (`apps/server/src/modules/mono/`):**

- `connection.ts:98` вже викликає `https://api.monobank.ua/personal/client-info`, але споживає ЛИШЕ `accounts` (`clientInfo.accounts ?? []`, ~рядок 142). Відповідь mono містить і `jars` — розшир обробку: зберігати jars поруч з accounts у наявному сховищі синку (подивись, як персистяться accounts — той самий патерн; двофазність міграцій Hard Rule #4, якщо потрібна нова таблиця/колонка).
- Знайди, звідки web отримує accounts при синку (`sync-state`/backfill/webhook-плейн) — jars мають їхати тим самим маршрутом. **Hard Rule #1:** усі bigint → number у серіалізаторі. **Hard Rule #3:** зміна response shape = server serializer + `packages/api-client` типи + contract-тест В ОДНОМУ PR (тип `MonoJar` у `packages/api-client/src/endpoints/mono.ts:73` вже існує — звір з реальною формою відповіді mono: `id`, `title`, `balance` (копійки), `goal` (копійки, nullable), `currencyCode`).
- Webhook: перевір, чи statement-події по банках приходять (jar має власний account-id у mono). Якщо ні — достатньо рефрешу client-info при синку (§ рішення 5).

**Web (`apps/web/src/modules/finyk/`):**

- `components/budgets/GoalBudgetCard.tsx` — прибрати редаговане поле «Відкладено» (після #468 воно з Label); показати прогрес (банка + поповнення, з розбивкою «з банки … / вручну …» коли є обидва), кнопку «+ Поповнити», згорнутий список історії.
- `components/budgets/AddBudgetForm.tsx` — дропдаун банки (+ дефолт суми цілі з jar.goal).
- Сховище: тип бюджету-цілі (грепни, де оголошений `Budget`/`GoalBudget` — finyk-domain) + нове поле `linkedJarId?` і масив поповнень. Патерн збереження — як інші finyk-слоти (storage-wrapper, sqliteWriter specs за наявним зразком).
- Доменна математика — чиста функція в `packages/finyk-domain` (прогрес з jar-балансу + поповнень), unit-тести обовʼязково. Гроші — копійки як `number` на межах, UAH у UI через наявні форматери.
- Quick-stats/Огляд цілей — перевір усі місця, що читають `savedAmount`, і переведи на нову функцію прогресу (грепни `savedAmount` по репо).

```bash

```

Обовʼязкові тести: прогрес = jar + поповнення; ціль без банки = сума логу; міграція savedAmount → перший запис; contract-тест jars (Hard Rule #3); видалення поповнення перераховує прогрес. Клік-тур: створити ціль з банкою → прогрес підтягнувся; «+ Поповнити» 500 → прогрес виріс, запис в історії; видалити запис → відкат.
