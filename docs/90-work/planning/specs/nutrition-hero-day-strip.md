## Проблема

Hero дашборду Їжі (`NutritionDashboard.tsx`, `prominence="hero"`) складається з великого `ProgressRing` (96px) і трьох макро-кілець по 48px. Аудит анти-слопу ([`2026-09-01-anti-slop-audit.md`](../../audits/2026-09-01-anti-slop-audit.md), F6/Q3) зафіксував, що всі чотири модулі мають один hero-шаблон «число + підпис + кільце/кнопка», а кільце прогресу — найпоширеніший атрактор трекерів калорій, тобто hero не проходить тест підміни. Крім того, кільце відповідає лише на «скільки зʼїв», а не на робоче питання дня «скільки лишилось і на що».

## Мета

Hero Їжі стає **стрічкою дня**: одна горизонтальна смуга, поділена на чотири прийоми за `MEAL_ORDER`, де ширина сегмента пропорційна калоріям, а порожній залишок підписаний «лишилось на <наступний незаписаний прийом>». Головне число — залишок до норми. Макро йдуть трьома тонкими смугами внизу hero. Кілець у hero немає. Форма даних (день як послідовність прийомів) відрізняє hero Їжі від hero інших модулів без зміни палітри.

## Рішення дизайну

Кожен пункт — ухвалене рішення founder-а (інтервʼю 2026-09-01, раунд 1), не Q&A.

1. **Сегменти стрічки — чотири типи прийомів за `MEAL_ORDER`** (`packages/nutrition-domain/src/mealTypes.ts`: breakfast → lunch → dinner → snack, підписи Сніданок · Обід · Вечеря · Перекус). Порядок фіксований, не за часом запису. Тип без записів рендериться **сірим сегментом мінімальної ширини з підписом «—»**, щоб стрічка завжди мала чотири позиції і читалась як розклад дня. Відкинуто: «фактичний порядок записів» — тоді стрічка різна щодня і не показує, чого ще бракує.
2. **Підпис залишку «лишилось на …» = перший ще не записаний тип за порядком дня.** Є сніданок і обід → «лишилось на вечерю»; є сніданок, обід, вечеря → «лишилось на перекус»; записані всі чотири → «лишилось сьогодні». Порожній день → «лишилось на сніданок». Відкинуто: підпис за годиною через `mealTypeByHour` — він суперечить факту, коли обід записано о 17:00.
3. **Без норми (`prefs.dailyTargetKcal` ≤ 0) — стрічка без залишку + CTA «Задати норму».** Сегменти будуються за фактом і разом займають 100% ширини (частка кожного прийому в зʼїденому); головного числа немає, замість нього CTA `Button` на `onGoToDailyPlan` (норму задають у денному плані, `DailyPlanGoalSelectors.tsx`). Порожній день без норми — той самий CTA і чотири сірі «—». Відкинуто: ховати hero без норми — новий користувач втрачає точку входу.
4. **Макро — три тонкі смуги внизу hero** (білки / жири / вуглеводи, факт / ціль, `tabular-nums`), а не кільця. `MacroRings` лишається компонентом для інших екранів (журнал, тижневий огляд) і НЕ видаляється в цьому PR. Без норми макро-смуги показують лише факт без цілі (як і головне число).
5. **Головне число — залишок `kcalGoal − kcalConsumed`**, `text-style-display` у `text-hero-ink`. Відʼємний залишок показуємо чесно: «−180 ккал понад норму», сегмент, що перетнув межу норми, дістає акцентний тон (tier-400 `nutrition`, без червоного — hero не карає, див. канон §5.2 «чесність незавершеного дня»).
6. **Неповний день (`isIncompleteDay`, < 3 прийоми) лишається чесним:** підпис під числом не каже «дефіцит», а лише «записано N із 4». Це збережена поведінка, не нова.
7. **Тост «Денну норму виконано»** (рядок 153 дашборду) не чіпаємо.

```bash
pnpm --filter @sergeant/web test -- nutrition          # нові й оновлені тести зелені
pnpm --filter @sergeant/web typecheck

SERGEANT_HEAVY_OK=1 pnpm --filter @sergeant/web size:eager   # eager ≤ 280 kB (hero у критичному шляху nutrition-чанка, не index)
```

Click-through у демо-режимі (`pnpm dev:web`, viewport 393×852, світла й темна тема):

1. `/nutrition` із демо-даними (є норма, два прийоми) → hero показує стрічку з чотирма позиціями, два заповнені сегменти з підписами й ккал, два сірі «—»; головне число = норма − факт; підпис «лишилось на вечерю»; три макро-смуги внизу. Кілець немає.
2. Додати вечерю через «+» → сегмент «Вечеря» зʼявляється, підпис стає «лишилось на перекус». Додати перекус → «лишилось сьогодні».
3. Додати прийом, що перевищує норму → число «−N ккал понад норму», останній сегмент акцентного тону, тост норми спрацьовує як раніше.
4. Зняти норму в денному плані (0) → у hero немає головного числа, є CTA «Задати норму» (≥44px на coarse pointer), сегменти заповнюють 100% ширини за фактом.
5. Порожній день без норми → чотири «—» і CTA.
6. Скрінрідер: стрічка має `role="img"` з `aria-label` виду «Сніданок 520 ккал, обід 720 ккал, вечеря не записана, перекус не записаний, лишилось 960 ккал на вечерю»; сегменти самі не фокусуються.

Нові тести й що вони ловлять:

- `nutritionStats.test.ts`: `mealTypeKcalForDay` — сума за типами для одного дня, ігнорування інших днів, фолбек за label.
- `nextMealLabel.test.ts`: пʼять станів підпису (порожній / після сніданку / після обіду / після вечері / усі чотири).
- `DayStrip.test.tsx`: рендер чотирьох позицій завжди; ширина сегментів пропорційна ккал при нормі й 100% без норми; акцент лише на сегменті, що перетнув норму; CTA без норми; `aria-label`.
- `NutritionDashboard.test.tsx`: у hero немає `ProgressRing`/`MacroRings`; є стрічка; існуючі тести тосту норми лишаються зеленими.

Playwright-аудит 44px (`pnpm --filter @sergeant/web e2e:mobile`) — блокуючий гейт у CI; CTA «Задати норму» має пройти.

## Ризики та відкриті питання

- **Дуже малий сегмент (перекус 50 ккал на 2 200) стає нечитабельним.** Рішення для виконавця: мінімальна ширина сегмента 12px, підпис ккал ховається за `min-width` через `@container`, повне значення лишається в `aria-label`.
- **Мобільний `text-style-display` 40px + чотири підписи** на 361px корисної ширини — підписи прийомів короткі (Сніданок 8 символів), але при 4 заповнених сегментах можуть не влізти; фолбек — перша літера з повним словом у `title`. Перевірити на 393px у кроці 2.
- **Канон §5.2 «чесність незавершеного дня»** — стрічка природно показує незавершеність (сірі «—»), тож поріг `< 3` як текстовий підпис може стати надлишковим. Не знімати в цьому PR; зафіксувати в журналі як спостереження.
- **Демо-дані** (`apps/web/src/core/onboarding/demo*`) можуть не мати `mealType` у прийомах — тоді працює фолбек `mealTypeFromLabel`; перевірити на кроці 1, що жоден демо-прийом не впав у «snack» помилково.
