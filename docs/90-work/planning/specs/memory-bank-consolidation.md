# Спека: один редактор фактів профілю (банк памʼяті × «Памʼять ШІ»)

> **Last touched:** 2026-08-30 by @Skords-01. **Next review:** 2026-12-30.
> **Status:** Active (спека до виконання)
> **Виконання:** чиста сесія у свіжому worktree від main. Governing skills: `sergeant-module-ai` + `sergeant-web-ui`. Мобайл поза скоупом.

## Проблема

Факти, які людина заявила про себе, видно у двох місцях з різними діями і різною свіжістю: Профіль → «Банк памʼяті» (редагування, локальний кеш) і Налаштування → «Памʼять ШІ» (незворотне видалення, серверний список `ai_memories`). Це два редактори одного списку. Додатковий дефект: після видалення profile-факту в «Памʼяті ШІ» локальний кеш не оновлюється до наступного перезавантаження сторінки, тож чатовий інструмент `my_profile` ще бачить «видалений» факт (кеш-лаг).

## Ціль

Один редактор фактів профілю (Профіль → «Банк памʼяті»), «Памʼять ШІ» стає вітриною авто-зібраного з навігацією до редактора. Кеш-лаг зникає разом із зайвими delete-кнопками. Модель даних ратифікується в каноні, щоб «три сховища» перестали виглядати безладом.

## Модель даних (ратифікована, змін коду не потребує)

Ланцюг уже працює наскрізно, це НЕ три незалежні сховища:

```
локалка (кеш пристрою)  ⇄  user_profile JSONB (сервер, істина)  →  ai_memories (пошуковий індекс RAG)
```

- **Локалка** (`apps/web/src/core/profile/memoryBank.ts`, ключ `USER_PROFILE`): кеш для миттєвого читання чатовими інструментами `remember` / `forget` / `my_profile` (`apps/web/src/core/lib/chatActions/crossActions/memoryHandlers.ts`).
- **Write-through**: кожен локальний запис через `writeMemoryEntries` нотифікує `subscribeLocalMemoryEdit`, на який `useProfileWriteThroughBoot.ts` вішає `pushMemoryBankToServer` → `PUT /api/me/profile` (весь payload, обидві половини: біометрія + банк). Pull назад: той самий boot-хук, один раз на `userId` за сесію, LWW-reconcile.
- **Дзеркало у вектори**: `PUT /api/me/profile` (`apps/server/src/routes/me.ts`) викликає `mirrorProfileMemoryEntries` (`apps/server/src/modules/ai-memory/profileMirror.ts`), який diff-ить і додає нові факти в `ai_memories` (source=`profile`, `source_ref` = id запису банку) та прибирає зниклі. Тобто видалення факту в Профілі ВЖЕ доїжджає до векторів самостійно.
- `DELETE /api/ai-memory/:id` (`apps/server/src/modules/ai-memory/listRoute.ts`) для source=`profile` в одній транзакції чистить і вектор, і запис у `user_profile` (`removeMemoryBankEntry`). Роут лишається як є (це захисна когерентність для прямих викликів API), просто UI ним для profile-рядків більше не користується.

## Рішення (зафіксовані founder-ом 2026-08-30)

1. **Профіль → «Банк памʼяті» = єдиний редактор фактів профілю.** Додавання, редагування, видалення тільки там. Видалення propagate-иться на сервер і у вектори наявним ланцюгом (push → mirror diff), нових механізмів не треба.
2. **Налаштування → «Памʼять ШІ» = вітрина авто-зібраного.** Група source=`profile` більше не рендериться як список рядків із delete-кнопками. Замість неї одна статична картка: людська назва («Факти профілю»), кількість фактів у групі, кнопка/лінк «Редагувати в профілі», що веде на hub-таб профілю. Решта груп (chat, finyk, fizruk, nutrition, routine, journal, digest, legacy cofounder/product) поводяться як зараз.
3. **Кеш-лаг не лікується окремим кодом** - він зникає, бо єдиний шлях видалення profile-факту тепер починається з локалки (вона свіжа за визначенням). «Стерти все» у `PrivacySection.tsx` вже чистить і локалку (`writeMemoryEntries([])`), не чіпати.
4. **API не змінюється.** `AiMemoryListItem` не розширюється, роути не чіпаються, Hard Rule #3 тріплет не рухається. Це суто web-UI + канон.

- `apps/web/src/core/settings/AiMemoryList.tsx`: у групуванні за source виділити гілку `source === "profile"` і рендерити навігаційну картку замість розкривної групи з рядками. Лічильник фактів: довжина profile-групи із уже завантажених сторінок (точність «скільки завантажено» прийнятна; не робити окремий запит).

Тон за `docs/01-product/copy/style-guide.uk.md`: наприклад, заголовок «Факти профілю», пояснення «Це ти розповідаєш про себе сам. Редагуються в профілі», дія «Відкрити профіль». Точний текст на розсуд виконавця в межах стайлгайду.
