# MCP-сервери та зовнішні API: ландшафт після Сільпо

> **Last validated:** 2026-08-25 by @claude (research)
> **Next review:** 2026-11-25.
> **Status:** Active — дослідження під рішення, не рішення

**Навіщо цей файл.** Founder-запит 2026-08-25: «чи є ще якісь MCP та інші
тулзи, які нам могли би допомогти чи зробити класну фічу, як це відбулося
із Сільпо». Тут — систематичний прохід по кандидатах: офіційні MCP-сервери,
відкриті API українських сервісів і платформні можливості, з оцінкою
цінності для модулів Sergeant і чесним списком того, що перевірено й НЕ
підходить. Живі OAuth/API-інтеграції явно поза скоупом ініціативи
[0022 (CSV-імпорт)](../initiatives/0022-import-from-external-trackers.md) —
цей док і є вхідними даними для тієї «окремої ініціативи».

---

## 1. Що зробило Сільпо-інтеграцію вдалою (шаблон для оцінки)

З [спеки Silpo MCP](../planning/specs/silpo-mcp-integration.md) виводиться
чотири критерії, за якими нижче оцінюється кожен кандидат:

1. **Офіційний API/MCP**, не скрейпінг — стабільність і легальність.
2. **Персональні дані користувача через OAuth/токен** — те, що людина
   вже накопичила деінде, а не порожній старт.
3. **Замикає наявну петлю без нового ручного вводу** — чек розгортає
   mono-транзакцію, поповнює комору; не «ще одна фіча збоку».
4. **Дані снапшотяться у наш PG** — фіча переживає смерть зовнішньої
   платформи.

Побічний бонус Сільпо, який тепер працює на нас: у
`apps/server/src/modules/silpo/mcpClient.ts` вже є **мінімальний власний
MCP-клієнт** (JSON-RPC поверх streamable HTTP, без нових залежностей) —
другий зовнішній MCP підключається значно дешевше за перший, і саме
другий споживач за задумом виправдає узагальнення адаптерної межі.

### 3.1 Strava — перший «другий MCP» (fizruk)

[Strava запустила офіційний MCP-конектор 2026-06-01](https://press.strava.com/articles/strava-launches-mcp-connector)
— read-only доступ до активностей, стрімів пульсу/темпу, GPS-маршрутів
через OAuth. Це найближчий структурний аналог Сільпо: офіційна платформа
відкрила персональні дані користувача для AI-клієнтів. Паралельно живе
класичний [Strava API v3](https://developers.strava.com/docs/getting-started/)
(OAuth, `/athlete/activities`, ліміти per-athlete).

- **Петля, яку замикає:** кардіо-гілка fizruk сьогодні — ручні моментні
  записи; бігуни/велосипедисти вже мають історію в Strava. Авто-імпорт
  активностей → стрік, digest-кореляції «тренування↔білок/витрати»
  годуються без вводу. Ініціатива 0022 давала лише разовий CSV-архів —
  живий sync сильніший і не конкурує з нею.
- **Складність:** S–M — `mcpClient.ts` + патерн `silpo_connection`
  (tokenStore, key ring, kill switch) реюзаються майже дослівно.
- **Ризики:** Strava з 2026 ввела платний developer fee і ретаєрить
  ендпоінти (Club-ендпоінти зникають 2026-09-01); офіційний MCP —
  для підписників Strava. Обидва шляхи (MCP vs API v3) звірити на
  спайку за зразком Silpo §0.

### 3.2 HealthKit / Health Connect — авто-вхід fizruk (mobile)

Не зовнішній API, а нативний шар iOS/Android: кроки, тренування, сон,
вага з десятків апок і носимих пристроїв одним каналом, локально, без
жодної зовнішньої платформи і токенів.

- **Петля:** fizruk — єдиний модуль без жодного авто-входу (finyk має
  mono, nutrition — чеки/комору). «Фінанси самі через webhook» — а
  кроки/тренування ні. Це найбільший розрив у «бачить усе життя разом».
- **Складність:** M–L і лише mobile: Expo потребує dev-client +
  prebuild (`react-native-health` / Health Connect); web-паритету немає
  принципово. Ініціатива 0022 §Фаза 4 свідомо обходила це файлом
  `export.xml` — нативний sync це скасовує.
- **Застереження:** персона «не біохакер» — імпортуємо мінімальний
  набір (тренування, кроки, вага, сон), не глибину метрик.

### 3.3 Відкритий банкінг НБУ — finyk поза Mono

З 1 серпня 2025 [банки зобов'язані відкрити API за стандартом НБУ](https://bank.gov.ua/en/payments/open-banking);
станом на серпень 2026 [Ощадбанк, OTP і Sense вже запустили](https://minfin.com.ua/ua/2026/08/05/179093822/),
ПУМБ/Приват/Укрсиб авторизовані, до кінця 2026 очікуються всі банки.
Канон finyk прямо каже: «інші банки не мають токенів, тому mono центр» —
цей зовнішній факт **перестає бути правдою**, і Privat-стек, що «чекає
зовнішнього фактора», отримує свій фактор.

- **Петля:** та сама, що в mono — транзакції без ручного вводу, але для
  клієнтів будь-якого банку. Найбільше розширення аудиторії finyk.
- **Складність:** L, і вона не в коді: доступ AISP вимагає реєстрації
  в НБУ + кваліфікованого сертифіката, або посередника-агрегатора
  ([Salt Edge заявляє покриття України](https://www.saltedge.com/products/account_information/coverage/ua)).
  Вартість/умови агрегатора для соло-продукту — головне невідоме.
- **Наступний крок:** не код, а спайк-дослідження: умови Salt Edge (чи
  іншого агрегатора) для України vs власна реєстрація; глибина історії;
  які банки реально віддають транзакції, а не лише баланси.

### 3.4 Sergeant як власний MCP-сервер — дзеркальний хід

Сільпо відкрили MCP — і Sergeant став для них AI-клієнтом. Дзеркало:
**Sergeant відкриває власний MCP** (read-only, OAuth, scopes), і founder
питає у Claude Desktop «скільки я витратив на каву за місяць і як це
корелює з тренуваннями» — поверх власних даних усіх чотирьох модулів.

- **Петля:** пряма матеріалізація ідентичності «бачить усе життя разом»
  у будь-якому AI-клієнті; для founder-персони (активний користувач
  Claude) — цінність з першого дня. Strava-прецедент показує, що це
  стає нормою для персональних платформ.
- **Складність:** M — REST-поверхня і auth вже є; треба MCP-обгортку
  (streamable HTTP, той самий протокол, що ми вже клієнтимо), токени за
  патерном`silpo_connection` навпаки, і жорсткі read-only scopes.
- **Гейти:** приватність — це найчутливіші дані продукту в зовнішньому
  LLM-контексті; текст обіцянки і маскування (конституція §9.9) — до
  будь-якого rollout-у, за уроком Silpo-гейта.

### 3.5 Нова Пошта API 2.0 — посилки в «моєму дні»

[Офіційний відкритий API](https://api-portal.novapost.com/uk/) з
безкоштовним ключем, стабільний роками.

- **Петля:** hub — «самостійна поверхня мій день»: картка «сьогодні
  приїде посилка» — це рівно той тип моментного контексту, що робить
  ранковий ритуал корисним; у finyk накладені платежі/доставки
  матчаться з витратами (патерн Silpo-matcher-а).
- **Складність:** S. Обмеження: трекінг вимагає номер ТТН + телефон;
  «всі мої посилки» без бізнес-кабінету API не віддає — реальний
  UX-скоуп звірити на спайку (можливо, лише ручне додавання ТТН —
  тоді цінність падає до ★☆☆).

### 3.6 Погода (Open-Meteo) — найдешевша нова кореляційна вісь

[Open-Meteo](https://open-meteo.com/) — безкоштовний, без ключа,
історія + прогноз.

- **Петля:** `digestCorrelations` отримує детерміновану вісь
  «погода/тиск/довжина дня ↔ настрій/звички/тренування/витрати» — нові
  пари для тижневого дайджесту без жодного вводу і жодного OAuth.
  Пороги hub-coach §6.2 обов'язкові, як для всіх кореляцій.
- **Складність:** S (один HTTP-клієнт + кеш по геолокації міста).

### 3.7 Google Calendar — низький пріоритет

Контекст дня в hub (зустрічі → менше тренувань → інсайт). OAuth-verification
процес Google для sensitive scopes — непропорційно дорогий для соло-продукту;
відкласти, поки hub-ритуал не доведе попит на календарний контекст.

## 4. Перевірено і НЕ підходить зараз

- **АТБ, Novus, Fora, інші рітейлери** — публічних API/MCP немає
  (станом на 2026-08 [Сільпо — єдиний офіційний рітейл-MCP України](https://dou.ua/forums/topic/61352/));
  чеки цих мереж уже покриті ДПС-шляхом. Другий рітейлер-MCP — тригер
  узагальнення адаптера (Silpo-спека § Поза скоупом), але його ще не існує.
- **Rozetka / Glovo / Zakaz.ua** — лише seller/partner API для
  мерчантів; персональної історії замовлень покупця не віддають.
- **Дія** — публічного API для сторонніх застосунків немає.
- **Checkbox** — API для мерчантів (видача чеків), покупцю не потрібен;
  наш вхід — реєстр ДПС.
- **Community monobank-MCP** — існує, але нам не потрібен: пряма
  інтеграція mono вже глибша.
- **Garmin / Whoop / Oura** — партнерські програми з ревʼю-процесом;
  плюс персона «не біохакер» — HealthKit/Health Connect агрегує їх
  безкоштовно як побічний ефект.
- **ДПС е-чек як «нова» ідея** — вже зроблено (receipt-scan, PR #818+).

## 5. Рекомендована послідовність (пропозиція, рішення за founder-ом)

1. **Швидкі перемоги (S):** Open-Meteo у digest-кореляції; спайк Нової
   Пошти (визначити чесний UX-скоуп до будь-якого коду).
2. **Стратегічний наступний MCP (S–M):** Strava — другий споживач
   `mcpClient.ts`, закриває кардіо-розрив fizruk, повторює перевірений
   Silpo-плейбук (спайк → walking skeleton → треки).
3. **Найбільший продуктовий розрив (M–L):** HealthKit/Health Connect —
   єдиний шлях зробити fizruk «сам», але вимагає мобільної зрілості
   (dev-client, EAS).
4. **Найбільша фін-цінність, найдовший шлях (L):** відкритий банкінг —
   почати зі спайку умов агрегаторів уже зараз, бо строк — місяці.
5. **Дзеркальний хід (M):** Sergeant-MCP — після формулювання
   privacy-обіцянки; технічно найдешевший «вау» для founder-персони.

## 6. Спільні інваріанти для будь-якої нової інтеграції (уроки Silpo)

Плейбук [`onboard-external-api.md`](../../00-start/playbooks/onboard-external-api.md)
+ перевірене спекою Silpo: kill-switch env-прапорець з першого дня;
токени — AES-GCM + key ring (`tokenStore`-патерн, single-flight refresh);
снапшот даних у власному PG; деградація до staleness-банера, ніколи до
помилки в core-флоу; snapshot-тест зовнішнього контракту в CI;
privacy-текст затверджується ДО rollout-у за межі founder-акаунта;
глобальний rate-budget, якщо client_id спільний на всю базу.
