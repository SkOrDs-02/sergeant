# Закрита бета — тимчасова інфраструктура

> **Last touched:** 2026-07-30 by @Skords-01. **Next review:** 2026-10-28.
> **Status:** Scaffolded — уся тека тимчасова. Живе рівно стільки, скільки триває закрита бета.

**Термін: 2026-10-31.** Після цієї дати тека або видаляється, або дата свідомо пересувається.

Ця тека існує, щоб запуск бети не розповз по репо й не лишився в ньому назавжди. Усе, що тут є, — одноразове: воно потрібне на час закритої бети й підлягає видаленню одразу після неї.

**Інструкція:** [`run-beta-wave.md`](./run-beta-wave.md) — повний порядок від підготовки до згортання.

## Чому окремо, а не серед playbook-ів

Плейбуки в [`docs/00-start/playbooks/`](../../00-start/playbooks/README.md) — це процедури, які повторюються роками: додати ендпоінт, полагодити CI, відкотити реліз. Закрита бета трапляється один раз. Якби цей док лежав там, він через рік виглядав би як чинна процедура — і хтось діяв би за нею, посилаючись на Vercel-проєкт, якого вже немає.

Тому: окрема тека, статус `Scaffolded` і дата вище.

Нагадає про прибирання **не цей файл, а два скрипти** — вони несуть маркери `AI-LEGACY: expires 2026-10-31`. Прострочений маркер валить `pnpm lint:ai-legacy` на PR і щотижня відкриває GitHub-issue. Сканер [`scripts/check-ai-legacy.mjs`](../../../scripts/check-ai-legacy.mjs) навмисно читає лише TS/JS-файли (у прозі маркер згадується як приклад — це давало б вічні false positive), тож у `.md` такий маркер був би декоративним. Якір enforcement-у — код, і це правильно: саме код і має померти.

## Що прибрати

Коли бета скінчиться (після Фази 4 в [`run-beta-wave.md`](./run-beta-wave.md)):

| Що                                        | Дія                                          |
| ----------------------------------------- | -------------------------------------------- |
| `docs/90-work/beta-launch/`               | видалити теку цілком                         |
| `scripts/telegram/broadcast-waitlist.mjs` | видалити                                     |
| `scripts/billing/grant-beta-pro.mjs`      | видалити                                     |
| `scripts/telegram/setup-webhook.mjs`      | видалити, якщо бот виводиться з експлуатації |
| Vercel-проєкт бети                        | видалити **проєкт**, не домен                |
| Домен бекенда в Coolify                   | змінити                                      |
| `TELEGRAM_WAITLIST_*` у Coolify           | прибрати разом із ботом                      |

**Чого НЕ чіпати:**

- Таблицю `telegram_waitlist` і міграцію `089`. `opted_out_at` — це пам'ять про те, що людина попросила їй не писати. Прогнати `089_*.down.sql` означає забути ці відмови, і при наступному вейтлісті ті самі люди отримають лист, від якого відписались. Таблиця маленька; лишити.
- Рядки в `subscriptions` зі `status = 'canceled'`. Це історія того, кому й коли видавався доступ.
- Сам Telegram-бот і його webhook — якщо вейтліст лишається робочим інструментом і після бети.
