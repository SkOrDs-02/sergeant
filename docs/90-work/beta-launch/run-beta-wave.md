**Trigger:** Час відкрити доступ черговій групі людей із Telegram-вейтліста — або згорнути хвилю бети й забрати доступ назад.

- Coupled surface: `apps/web` (окремий Vercel-проєкт бети), Telegram-бот вейтліста
- Governing skill: `sergeant-deploy-and-observability`

## Чому саме такий порядок

Три залежності, які диктують послідовність:

1. **Стеля витрат ставиться першою.** `ANTHROPIC_BUDGET_HARD_DEGRADE_ALL` — єдине, що фізично обмежує рахунок за AI. Soft/hard-пороги без нього лише пишуть алерт і нічого не зупиняють. Вмикати після того, як люди зайшли, — означає лишити вікно без стелі.
2. **Розсилка йде до видачі Pro.** Pro видається по email, а email з'являється лише після реєстрації. До розсилки видавати нема кому.
3. **Група бети створюється до розсилки.** Порожній `TELEGRAM_BETA_INVITE_LINK` не валить скрипт — він тихо шле лист **без** посилання на групу. Тобто «доступ відкрито» без доступу.

## Фаза 0 — підготовка (один раз перед першою хвилею)

### 0.1 Стеля витрат на AI

У Coolify, у сервісі API:

```
ANTHROPIC_BUDGET_HARD_DEGRADE_ALL=true
```

Коли денний спенд Anthropic пробиває `ANTHROPIC_BUDGET_HARD_USD` (дефолт `5`), усі не-founder користувачі падають на дешеву модель замість того, щоб виставити рахунок далі. Без цього прапорця стелі немає.

Там же перевір:

- `STRIPE_ENABLED` — має лишатись `false`. Назва історична (Stripe виведено з експлуатації), але саме ця змінна вимикає серверний paywall.
- `AI_QUOTA_FOUNDER_IDS` — **тільки твій** Better-Auth ID. Founder обходить і квоту, і аварійний breaker; тестерам це не видають.

### 0.2 Група бети в Telegram

Створи групу, візьми invite-лінк, поклади його у своє локальне оточення як `TELEGRAM_BETA_INVITE_LINK`.

### 0.3 Окремий Vercel-проєкт для застосунку бети

**Окремий проєкт, а не окремий домен.** Причина — у фазі 4: видалення проєкту забирає і кастомний домен, і генерований `<project>.vercel.app`, і всі deployment-URL-и разом. Відкручений домен лишає `<project>.vercel.app` публічним, і на Hobby захистити його неможливо (див. [Vercel docs](https://vercel.com/docs/deployment-protection): production domain лишається публічним).

Налаштування проєкту:

| Поле                                 | Значення                                                                            |
| ------------------------------------ | ----------------------------------------------------------------------------------- |
| Root Directory                       | `apps/web`                                                                          |
| Include files outside Root Directory | **увімкнути** (інакше pnpm-воркспейс не збереться)                                  |
| Build / Install / Output             | лишити порожніми — їх задає [`apps/web/vercel.json`](../../../apps/web/vercel.json) |

Змінні оточення — розділ [«Змінні для бета-проєкту»](#змінні-для-бета-проєкту) нижче.

## Фаза 1 — розсилка інвайтів

Запускається з ноута. Потрібні три змінні: `DATABASE_URL` (публічний URL прод-бази — той самий, що для міграцій), `TELEGRAM_WAITLIST_BOT_TOKEN`, `TELEGRAM_BETA_INVITE_LINK`.

### 1.1 Подивитись, що піде і скільком

```bash
node scripts/telegram/broadcast-waitlist.mjs --dry-run
```

Друкує кількість адресатів і повний текст листа. Нічого не шле. **Читай текст очима** — після відправки редагувати нічого.

### 1.2 Перша хвиля

```bash
node scripts/telegram/broadcast-waitlist.mjs --limit 20
```

`--limit` існує не для економії. Як зреагують живі люди, суха перевірка не покаже: перші 20 скажуть, чи зрозумілий лист і чи витримує група потік. Далі `--limit 50`, далі решта.

### Як він поводиться

Черга — це `notified_at IS NULL AND opted_out_at IS NULL`. Після **кожного** успішного повідомлення скрипт одразу ставить `notified_at`, окремим запитом. Тому перерваний прогін (заснув ноут, обірвався інтернет) безпечно перезапустити: вже запрошені у вибірку не потраплять.

| Відповідь Telegram    | Дія                                               |
| --------------------- | ------------------------------------------------- |
| успіх                 | `notified_at = NOW()`                             |
| `403` заблокував бота | `opted_out_at = NOW()` — це відписка, а не збій   |
| `429`                 | чекає рівно `retry_after`, пробує **один** раз    |
| інше                  | нічого не ставить, наступний прогін спробує знову |

Темп — 50 мс між повідомленнями (~20/с) при стелі Telegram ~30/с.

### Свій текст

```bash
node scripts/telegram/broadcast-waitlist.mjs --dry-run --text "Привіт! Відкрив доступ..."
```

## Фаза 2 — видача Pro

Без Pro тестери не побачать частину того, що треба протестувати: аналіз фото їжі, AI-memory, мультивалютність, експорт у PDF, автосинк Monobank.

Гейт стоїть **двічі** — на сервері (`requirePlan`) і на клієнті (`useFeatureGate` → `usePlan`). Клієнтський спрацьовує першим і навіть не шле запит, тому `STRIPE_ENABLED=false` його не знімає. Єдине джерело істини — рядок у `subscriptions`.

Потрібна одна змінна: `DATABASE_URL`.

### 2.1 Побачити, хто зареєструвався

```bash
node scripts/billing/grant-beta-pro.mjs --list
```

Пошта, поточний план, дата реєстрації. Нічого не змінює. Тут ти зіставляєш акаунт із людиною з вейтліста — автоматично це не зв'язати, бо в бота є `chat_id`, а не пошта.

### 2.2 Перевірити

```bash
node scripts/billing/grant-beta-pro.mjs --emails a@b.com,c@d.com --dry-run
```

`--dry-run` тут **виконує всі справжні записи в транзакції й відкочує її**, а не друкує план. Тому суха перевірка ловить помилку в SQL до того, як та щось зачепить.

### 2.3 Видати

```bash
node scripts/billing/grant-beta-pro.mjs --emails a@b.com,c@d.com --days 14
```

Тестери побачать Pro після перезавантаження сторінки. Багато адрес — склади список у файл (по одній на рядок, `#` — коментар) і передай `--emails-file beta.txt`.

### Що зроблено навмисно

- **`--days` закриває бету саму.** Через N днів Pro відпадає без твоєї участі — забути відкликати доступ це нормальна людська справа.
- **Повторний запуск безпечний.** Дублів не буде, просто оновиться термін.
- **Справжню оплачену підписку скрипт скасувати не може.** Він працює лише з записами `provider = 'manual'` — тими, які сам і створив.
- **`status = 'trialing'`, не `'active'`** — щоб бета-доступи не змішались із реальними платниками в метриках, коли ті з'являться.

## Фаза 3 — під час бети

Стан вейтліста — командою `/stats` у боті (працює тільки з твого `chat_id`, заданого в `TELEGRAM_WAITLIST_ADMIN_CHAT_ID`):

```
Вейтліст: 24

Чекають:      4
Запрошені:    18
Відписались:  2

Канали:
  hero — 19
  footer — 5
```

`Чекають` — це черга наступної хвилі. Коли впаде до нуля, всі запрошені.

Витрати дивись у Coolify-логах за алертами `anthropic_budget_*`. Soft-поріг (`$3/день`) — сигнал, що темп вищий за очікуваний; hard (`$5/день`) — момент, коли всі падають на дешеву модель.

## Фаза 4 — згорнути бету

Порядок важливий: спершу забрати доступ у даних, потім прибрати поверхні.

### 4.1 Відкликати Pro

```bash
node scripts/billing/grant-beta-pro.mjs --emails-file beta.txt --revoke --dry-run
node scripts/billing/grant-beta-pro.mjs --emails-file beta.txt --revoke
```

Записи не видаляються — статус стає `canceled`. Це історія того, що доступ був виданий і коли забраний.

### 4.2 Видалити Vercel-проєкт бети

Саме **проєкт**, не домен. Разом із ним помирають і кастомний домен, і `<project>.vercel.app`, і всі deployment-URL-и.

### 4.3 Змінити домен бекенда в Coolify

Vercel-проєкт закриває UI, але бекенд має власний публічний хостнейм, і він буде в Network-панелі у кожного тестера. `POST /api/chat` не вимагає сесії — анонім має 3 повідомлення на добу з IP. Зміна домену сервісу вбиває старий хостнейм.

### 4.4 Не переюзовувати хостнейм бети

Local-first сховище скоупиться по origin. Підняти щось на тому ж хостнеймі через півроку — воскресити в тих самих людей беточні бази з несумісною схемою.

### Чого це не закриває

Тестер, який **встановив PWA**, збереже робочу офлайн-копію: оболонка в precache Service Worker-а, дані в браузері. Без AI, без синку, без оновлень — але запуститься. Відкликати це дистанційно неможливо, бо відкликання вимагало б мережі, без якої offline-first дизайн навмисно обходиться.

## Змінні для бета-проєкту

У Vercel → Settings → Environment Variables проєкту бети. Задавати для **Production**.

| Змінна                    | Обов'язкова | Де взяти                                                                                                                                                    |
| ------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BACKEND_URL`             | **так**     | Origin бекенда з Coolify (без шляху). Вмикає edge-проксі, і запити стають same-origin                                                                       |
| `VITE_POSTHOG_KEY`        | ні          | PostHog → Project Settings → Project API Key. **Той самий, що на лендінгу** — інакше воронка «клік у боті → реєстрація» розірветься на два незведені потоки |
| `VITE_POSTHOG_HOST`       | ні          | Дефолт `https://eu.i.posthog.com`; задавати лише якщо інстанс не EU                                                                                         |
| `VITE_SENTRY_DSN`         | ні          | sentry.io → Project Settings → Client Keys (DSN). Це DSN **браузера** — не той `SENTRY_DSN`, що стоїть у Coolify для сервера (див. нижче)                   |
| `VITE_SENTRY_ENVIRONMENT` | ні          | `beta` — щоб помилки тестерів не змішались із прод-помилками                                                                                                |

### Чого задавати НЕ треба

| Змінна                  | Чому                                                                                                                                                                                          |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITE_API_BASE_URL`     | Задаси — застосунок піде на бекенд напряму, в обхід проксі, і домен бети доведеться додавати в `ALLOWED_ORIGINS` на сервері. Лишити порожньою: тоді шляхи відносні й CORS не задіяний узагалі |
| `SITE_URL`              | Vercel підставляє `VERCEL_PROJECT_PRODUCTION_URL` сам                                                                                                                                         |
| `VITE_INTERNAL_API_KEY` | **Ніколи в прод-білді.** Це dev-only ключ; у бандлі він став би публічним (Hard Rule #20)                                                                                                     |

#### Що означає префікс `VITE_`

Vite — збирач фронтенду. Він бачить **лише** ті змінні, що починаються з `VITE_`, і **вкомпільовує їхні значення прямо в JS-бандл**, який їде в браузер. Звідси два наслідки:

- зміна `VITE_*` у Vercel UI **не діє, поки не перебілдиш** — це не рантайм-конфіг;
- усе, що з `VITE_`, стає **публічним**. Ніколи не клади туди секрет.

Тому одна й та сама річ має дві різні змінні на двох поверхнях:

| Поверхня                  | Змінна            | Де живе                           |
| ------------------------- | ----------------- | --------------------------------- |
| Сервер (Node на Coolify)  | `SENTRY_DSN`      | env сервера, читається в рантаймі |
| Браузер (бандл на Vercel) | `VITE_SENTRY_DSN` | вкомпільовується в JS             |

**Значення може бути те саме**, якщо хочеш бачити помилки сервера й браузера в одному Sentry-проєкті. Але краще завести два проєкти: у них різні стектрейси, різні алерти, і фронтові помилки тестерів не топитимуть серверні. DSN — не секрет за дизайном (він write-only, для того й придуманий, щоб лежати у браузерному коді), тож у бандлі йому нормально.

Те саме стосується `VITE_POSTHOG_KEY`: це публічний ключ проєкту, а не приватний API-ключ.

#### Що саме класти в `BACKEND_URL`

Це **публічний** URL API — той самий хост Coolify, який віддає `/api/*`. Не внутрішня адреса: middleware виконується на edge-мережі Vercel, тож ходить ззовні через інтернет.

- **Тільки origin**, без шляху. Значення проходить через `backendUrl.origin` ([`apps/web/middleware.ts`](../../../apps/web/middleware.ts)), тому `https://api-хост/api` мовчки втратить `/api`. Правильно — `https://api-хост`.
- **Тільки `https://`** (виняток — `localhost`). Інша схема робить middleware no-op, щоб проксі не даунґрейднувся на незашифрований канал.
- **Без префікса `VITE_`** — принципово: `VITE_*` потрапляють у клієнтський бандл, а `BACKEND_URL` читається на сервері й лишається там.

Значення те саме, що пішло б у `VITE_API_BASE_URL`. Різниця в тому, хто ходить на бекенд: тут — edge Vercel (запити same-origin, CORS не задіяний), там — браузер напряму, і домен бети довелося б додавати в `ALLOWED_ORIGINS`.

### Змінні для скриптів (локально, не у Vercel)

| Змінна                        | Для чого       | Де взяти                                                              |
| ----------------------------- | -------------- | --------------------------------------------------------------------- |
| `DATABASE_URL`                | обидва скрипти | Публічний URL прод-бази — той самий, що використовується для міграцій |
| `TELEGRAM_WAITLIST_BOT_TOKEN` | розсилка       | BotFather                                                             |
| `TELEGRAM_BETA_INVITE_LINK`   | розсилка       | Invite-лінк групи бети                                                |

Це секрети. Не комітити, не вставляти в чати, не друкувати в логах.
