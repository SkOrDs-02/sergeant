# Аудит іконок і емодзі в UI

> **Поточні статуси перенесених знахідок:** [єдиний реєстр верифікації](verification/findings.json). Цей документ зберігає історичні результати; нові спроби та виправлення ведуться в реєстрі.

> **Last touched:** 2026-09-05 by @Skords-01. **Next review:** 2026-12-05.
> **Status:** Active — веб закрито цим PR; мобільні пікери емодзі лишаються відкритим боргом (§5).

> **Привід.** Репорт тестувальника: «В лімітах є іконки, а у витратах немає. То
> так має бути?» плюс прохання зробити аудит і замінити смайли та емодзі.

---

## 1. Що насправді бачив тестувальник

Спостереження було точним, але діагноз навпаки: **іконок не бракувало у витратах —
їх бракувало в лімітах**, а те, що там виглядало як іконка, було емодзі.

Резолвери домену віддавали підпис категорії з емодзі-префіксом:

```
getExpenseCategoryForTransaction(...) → { id: "food", label: "🛒 Продукти" }
```

Далі поверхні розходились:

| Поверхня                            | Що робила з підписом                                  | Що бачила людина     |
| ----------------------------------- | ----------------------------------------------------- | -------------------- |
| Рядок транзакції (`TxRow`)          | зрізала префікс, малювала `<Icon>` у тонованому колі  | SVG-іконка в кольорі |
| Картка ліміту (`LimitBudgetCard`)   | рендерила підпис як є                                 | системне емодзі      |
| Алерти бюджету (`BudgetAlertsList`) | рендерила підпис як є                                 | системне емодзі      |
| Мобільний `TxRow`                   | `cat.label.split(" ")[0]` — брала префікс як «іконку» | системне емодзі      |

Тобто один факт («яка це категорія») жив у двох формах — гліф усередині рядка
й окрема таблиця іконок у вебі, — і кожна поверхня обирала свою. Це той самий
клас дефекту, який `manualTaxonomy.ts` уже фіксував 2026-08-13 для кольору й
підпису; емодзі тоді лишили.

**Чому емодзі не годиться як іконка.** Малюється системним emoji-шрифтом, тобто
різний вигляд на iOS / Android / Windows; не бере `currentColor`, тож не має ані
теми, ані стану; не масштабується разом із типографікою. Той самий висновок уже
записаний двічі в репо — у `packages/routine-domain/src/glyphs.ts` (перехід
Рутини на icon-slug-и, 2026-08-03) і в `AddBudgetForm.tsx` (іконки цілей,
2026-08-03).

## 2. Рішення

Один канонічний набір slug-ів на модуль, підпис завжди чистий:

- **Фінік** — `packages/finyk-domain/src/lib/categoryIcons.ts`:
  `CATEGORY_ICON_SLUGS` (22 гліфи) + `categoryIconName(categoryId)`.
  Веб — `CategoryIconChip`; мобільний — `CategoryIcon` (`lucide-react-native`).
- **Харчування** — `iconName` замість `emoji` у `MEAL_TYPES` і `FOOD_CATEGORIES`.
  Веб — `<Icon>`; мобільний — `NutritionIcon`.
- **Рутина** — уже мала `glyphs.ts`; тут виправлено лише два місця, які обходили
  резолвер і друкували slug як текст (§4).

Ключова частина — **де** зрізається емодзі. Не на кожному рендері (це і був
дефект: хто знав про префікс, той зрізав, хто не знав — показував), а в даних:
`ManualCategoryDef.emoji` і `taxonomyLabel()` видалені, `MCC_CATEGORIES[].label`
чисті. Розійтись поверхням більше немає на чому.

### Джерела в домені

| Файл                                                    | Було                                             | Стало                                  |
| ------------------------------------------------------- | ------------------------------------------------ | -------------------------------------- |

| `finyk-domain/lib/manualTaxonomy.ts`                    | поле `emoji`, `taxonomyLabel()`                  | видалені; `iconName: CategoryIconName` |
| `finyk-domain/lib/categoryIcons.ts`                     | —                                                | **новий** — закритий набір + резолвер  |
| `finyk-domain/lib/categories.ts`, `domain/selectors.ts` | fallback `"💳 Інше"`                             | `"Інше"`                               |
| `finyk-domain/lib/formatting.ts`                        | 9 підписів рахунку з емодзі                      | чисті                                  |
| `finyk-domain/domain/debtEngine.ts`                     | 7 підписів ролей з емодзі                        | чисті; парну гілку `origin` знято¹     |
| `finyk-domain/domain/budget.ts`                         | `"Ціль досягнута 🎉"`                            | `"Ціль досягнута"`                     |
| `finyk-domain/domain/overview.ts`                       | `${d.emoji \|\| "💸"} ${d.name}`                 | `d.name`                               |
| `nutrition-domain/mealTypes.ts`, `foodCategories.ts`    | `emoji`                                          | `iconName`                             |
| `routine-domain/calendarEvents.ts`                      | `${sub.emoji \|\| "📱"} ${sub.name}`             | `sub.name`                             |
| `insights/recommendations/finance/*.ts`                 | 8 полів `icon:` з емодзі                         | імена гліфів                           |

¹ `debt` і `receivable` різнились у ролі `origin` **рівно емодзі** (📥 проти 📤) —
текст був однаковий. Тобто напрямок руху грошей ніс символ, який не мав ані
кольору, ані теми. Разом з емодзі зникла й різниця, тож розгалуження прибрано.

### Веб

- `CategoryIconChip` — **новий** спільний компонент (тонований круг + іконка
  категорії), винесений із `TxRow`. Тепер його вживають `TxRow`,
  `LimitBudgetCard`, `BudgetAlertsList`, `TransactionsBatchToolbar`.
- `LimitBudgetCard` — іконка з'явилась у режимі перегляду й замінила generic
  `calendar` у режимі редагування. **Це і є фікс із репорту.**
- `TransactionsBatchToolbar` — заповнено слот, який із 2026-07 рендерився
  порожнім (коментар на місці це визнавав, але не лікував).
- `HubInsightsPanel`, `TodayFocusCard` — знято текстову гілку подвійної
  конвенції `icon`. Вона існувала рівно для емодзі фінансових правил; тепер
  незнайоме імʼя не малює нічого, а не підсовує випадковий гліф.
- `Icon.paths.domain.tsx` — додано 4 гліфи (`apple`, `carrot`, `fish`, `wheat`)
  під категорії комори. Без них сім категорій довелося б звести до одного
  generic-гліфа, тобто втратити розрізнення.
- `useFinykStorageMutations` — підпис ВЛАСНОЇ категорії нормалізується на
  **записі** (`stripCategoryEmoji`), а не на кожному рендері. Підказка в
  налаштуваннях більше не пропонує «вказати емодзі на початку назви».
- Дрібне: статуси чату (`⏱`/`⏹`), статус сканера штрихкоду (`✔`).

### Мобільний

- `TxRow` — `cat.label.split(" ")[0]` замінено на `CategoryIcon`. Це не лише
  косметика: після зняття префікса стара логіка з'їдала б перше слово назви.
- `NutritionIcon` — **новий**; `MealTypePicker`, `Pantry`, `Log` на ньому.
- Маркер tool-call у чаті `✅` → `✓` (U+2713) — узгоджено з вебом, який зробив
  цю заміну раніше і задокументував причину: типографічний символ наслідує
  колір і шрифт повідомлення, емодзі — ні. TTS-фільтри обох платформ оновлені.

## 4. Два справжні баги, знайдені попутно

Обидва — наслідок переходу Рутини на icon-slug-и 2026-08-03: поле досі зветься
`emoji`, але містить імʼя іконки, і два місця клеїли його в текст як емодзі.

| Місце                                             | Що друкувалось                 |
| ------------------------------------------------- | ------------------------------ |
| `core/hub/search/searchSources.ts:213`            | `"droplet Пити воду"` у пошуку |
| `core/lib/chatActions/queryRoutineActions.ts:148` | те саме в тексті асистента     |

На легасі-записах там натомість лишалось сире емодзі — тобто рядок виглядав
по-різному залежно від віку запису. Гліф прибрано з тексту в обох місцях:
у пошуку й у чаті його немає чим намалювати.

## 5. Що НЕ закрито (свідомо)

### 5.1 Мобільні емодзі-пікери Фініка — головний залишок

`apps/mobile` має **справжні** пікери емодзі там, де веб їх не має:

| Файл                                                                     | Що саме                    |
| ------------------------------------------------------------------------ | -------------------------- |
| `modules/finyk/components/budgets/SubscriptionEditSheet.tsx`             | масив `EMOJIS` з 10 гліфів |
| `modules/finyk/components/budgets/AddBudgetSheet.tsx`                    | масив із 10 гліфів цілі    |
| `modules/finyk/components/assets/{ManualAsset,Debt,Receivable}Sheet.tsx` | дефолти 💰 / 💸 / 👤       |
| `modules/finyk/components/assets/rows.tsx`, `SubscriptionRow.tsx`        | рендер збережених значень  |

Це вибір користувача, збережений у даних, — не хардкод. Заміна вимагає того
самого, що Рутина зробила в `glyphs.ts`: закритий набір slug-ів, пікер іконок
замість пікера емодзі й read-time `upgrade*` для вже збережених значень. Це
окрема міграція з власним ризиком, і перевірити її можна лише на пристрої —
чого в цій сесії немає. **Рекомендований шлях:** повторити `glyphs.ts` один в
один, узявши `CATEGORY_ICON_SLUGS` за основу набору.

Поки цього немає, веб навмисно лишає засіяні дефолти `emoji` в
`useAssetsState.ts` / `AssetsForm.tsx`: веб їх більше не показує ніде, але
мобільний на них спирається, і обнулення зробило б там порожні слоти.

### 5.2 Мобільні емодзі поза Фініком

~60 місць: `SettingsGroup emoji=`, `QuickLinksRow`, `StatsPill`, порожні стани,
`searchActions`/`searchSources`, онбординг. Механічно просте, але велике й
неперевірюване без пристрою. Інвентар — `git grep -nP '\p{Extended_Pictographic}' apps/mobile/src`.

### 5.3 Стрілки в рядкових літералах

`"Усі →"`, `"Журнал →"`, `"↑ Покупка по картці"` — 6 місць. Репо має явну
конвенцію проти цього (`uk.finyk.ts:31`, `uk.fizruk.ts:241`: «стрілку малює
`Icon name="chevron-right"` на call-site»). Не емодзі, тож поза межами цього
PR, але той самий клас.

### 5.4 Мертві поля `emoji`

`DebtCard.emoji` (обовʼязковий проп, ніде не рендериться), `GoalBudgetCard.emoji`,
`SubCard` (round-trip через форму без рендера), `ModuleConfig.emoji`. Прибирати —
разом із §5.1, щоб не робити два проходи по тих самих файлах.

`DEFAULT_SUBSCRIPTIONS[].emoji` (7 гліфів у `finyk-domain/constants.ts`) сюди
**не** належить, хоч на перший погляд і виглядає мертвим: у вебі імпортерів
справді нема, але `apps/mobile/src/modules/finyk/lib/budgetsStore.ts:154` сідає з нього, а
`SubscriptionRow` цей гліф малює. Тобто це жива частина §5.1, не смітник.

### 5.5 Дубль таблиці підписів рахунку

`apps/web/src/modules/finyk/lib/accountVisual.ts` існував тому, що `getAccountLabel` домену
ніс емодзі. Тепер обидві таблиці чисті, тож дубль лишився без причини —
зведення в одну варте окремого PR.

## 6. Чим тримається (щоб не повернулось)

ESLint-правила `no-emoji-icon` більше немає — естетичні AST-правила retired
[ADR-0081](../../04-governance/adr/0081-repository-simplification.md), і
відкривати це рішення заново тут не варто. Натомість інваріант живе тестами
поруч із даними, де його не обійти:

- `finyk-domain/lib/manualTaxonomy.test.ts` — «жоден підпис не містить емодзі».
- `nutrition-domain/foodCategories.test.ts` — «жодна категорія не несе емодзі».
- `Record<CategoryIconName, …>` у `CategoryIcon.tsx` (мобільний) — новий
  доменний slug без іконки не компілюється.

Перевірка вручну на майбутнє:

```bash
git grep -nP '\p{Extended_Pictographic}' -- 'apps/web/src/**/*.tsx' 'packages/*/src/**/*.ts'
```
