# Активні спеки

> **Last touched:** 2026-09-17 by @claude (правило життєвого циклу: Implemented-спеки лишаються як as-built доказ). **Next review:** 2026-12-16.
> **Status:** Active
> **Spec-lint:** skip — каталог-індекс, а не фічева спека.

Це єдиний каталог фічевої роботи — і відкритої, і вже виконаної. Кожна спека
описує проблему, мету, межі, acceptance criteria та перевірку. Шаблон —
[`TEMPLATE.md`](./TEMPLATE.md).

Відкриті спеки (`Active` / `Draft` / `Scaffolded`) потрапляють до автогенерованого
[дашборда роботи](../../open-work.md). Після завершення спека **лишається в теці**
зі статусом `Implemented` і доказом у шапці (файли в коді або номер PR — статус
без доказу заборонений) плюс коротким блоком «Стан виконання» з residual-пунктами:
це as-built запис, за яким наступний аудит відтворює перевірку. Прибираються з
active checkout лише покинуті або superseded спеки (`Deprecated` / `Closed` із
вказівником на наступника); історія лишається в Git або ADR.

> Історично (до 2026-09-17) правило звучало «після завершення спека прибирається
> з active checkout» — на практиці його не дотримувались: у теці ~20 спек зі
> статусом `Implemented` / `Done` / `Closed`, і саме вони є доказом виконаного.

Під час міграції сюди перенесено активні матеріали з колишніх
`work/specs`, а legacy archive-дерева не розширюються.
