## 1. Модель: Freemium + підписка

Freemium — найкращий вибір для Sergeant, бо:

- Продукт вирішує щоденну проблему (tracking) — юзер повинен спробувати перед покупкою.
- Конверсія freemium для B2C productivity apps: **2–5 %** (медіана), **8–12 %** (топ-перформери).
  - Референс: [First Page Sage, 2021–2025](https://firstpagesage.com/reports/saas-conversion-rate-benchmarks/) (80+ SaaS): traditional freemium → paid = **3,7 %**; Financial/Fintech = **3,7 %**; Healthcare/MedTech = **4,0 %**. Free-trial → paid значно вищий: **8–25 %** ([Lenny Rachitsky, 2024](https://www.lennysnewsletter.com/p/what-is-a-good-free-to-paid-conversion)).
- Local-first архітектура дозволяє дати реальну цінність безкоштовно (дані локальні, сервер не потрібен для базових фіч).
- PWA не має 30 % комісії Apple/Google — маржа вища.

> **Benchmark:** MyFitnessPal (тільки їжа+фітнес) має 14M+ продуктів у базі та три тіри. YNAB (тільки фінанси) — $109/рік, 0 free-tier. Обидва вужчі за Sergeant, але з вищою ціною. Наш freemium з 4 модулями = ширший value prop за нижчою ціною.

## 3. Ціноутворення: ринковий контекст

> **Примітка щодо валюти.** Ціни на старті — у ₴ (UAH), бо:
>
> 1. **Цільовий ринок — Україна.** Гривневі ціни знижують когнітивний бар'єр: юзер бачить «₴199», а не «$4.52 → конвертувати → комісія».
> 2. **Perceived cost.** ₴199 — психологічно «менше двох сотень».
> 3. **Регуляторна простота.** ФОП може виставляти інвойси в UAH без валютних ліцензій.
> 4. Для англомовного ринку (фаза 4+) додамо USD-ціни: $4.99/міс.
>
> Курс: **₴1 ≈ $0.023** ([НБУ, квітень 2026](https://bank.gov.ua/ua/markets/exchangerates), ~₴44/$1). Тобто ₴199 ≈ **$4.52**, ₴1490/рік ≈ **$33.86**.

| --------------------- | --------------------------------------- | ----------------------------- | ---------------- | ---------- |
| MyFitnessPal Premium  | $19.99/міс або $79.99/рік               | Тільки їжа+фітнес             | myfitnesspal.com | 2026-02    |
| MyFitnessPal Premium+ | $24.99/міс або $99.99/рік               | +Meal Planner                 | myfitnesspal.com | 2026-02    |

> **Конкурентна перевага:** за ~$4.52/міс юзер отримує те, за що в окремих додатках платив би $50+/міс (MFP Premium + YNAB + Fabulous). Гривневі ціни знижують поріг для UA-ринку.

### Альтернативні ціни (для тесту)

- **₴149/міс** — якщо AI-фічі дійсно сильні.
- **$4.99/міс** — для англомовного ринку (подвійне ціноутворення UAH/USD).
- **Lifetime deal: ₴2999** — для ранніх адоптерів (early access hype).

## 4. Платіжні провайдери

### 4.1 Для PWA (основний канал — 0 % комісії платформи)

| Провайдер              | Комісія     | Підписки                        | UA ФОП      | Зусилля                        |
| ---------------------- | ----------- | ------------------------------- | ----------- | ------------------------------ |
| **Stripe**             | 2.9 % + 30¢ | Billing API, Customer Portal    | ✅          | Середні, найкраща документація |
| **LiqPay**             | 2.75 %      | Підписки є, API старіший        | ✅ (рідний) | Низькі                         |
| **Fondy**              | від 2.35 %  | Рекурентні платежі              | ✅          | Низькі                         |
| **Monobank Acquiring** | ~1.5 %      | Інвойсинг, не класичні підписки | ✅          | Високі (API сирий для subs)    |
| **Paddle**             | 5 % + 50¢   | Повний lifecycle + податки      | ✅ (MoR)    | Мінімальні (вони все роблять)  |
| **WayForPay**          | від 2.1 %   | Є рекурентні                    | ✅          | Низькі                         |

### 4.2 Decision tree: який провайдер обрати

```
Потрібен payment provider?
│
├─ MVP (Україна, ₴, ФОП)?
│   ├─ Хочеш мінімум зусиль?
│   │   └─► LiqPay — рідний для UA, рекурентні платежі, Mono-екосистема
│   └─ Хочеш нижчу комісію?
│       └─► Fondy (від 2.35 %) або WayForPay (від 2.1 %)
│
├─ Масштабування (міжнародні картки, webhooks, DX)?
│   └─► Stripe — Customer Portal, Billing API, invoices,
│       найкраща документація. Стає must-have при виході на EN-ринок.
│
├─ Не хочеш морочитися з податками (VAT, sales tax)?
│   └─► Paddle — Merchant of Record, вони все роблять.
│       Trade-off: 5 %+50¢ комісія (найвища).
│
└─ Нативні білди (Play Store / App Store)?
    ├─ Google Play Billing: 15 % (перші $1M/рік), далі 30 %
    └─ Apple IAP: 15 % (<$1M), далі 30 %
        └─ Можна направляти юзерів на веб для оплати
           (як Spotify/Netflix) — легально, але Apple воює.
```

**Прескриптивний висновок для Sergeant** _(historical, травень 2026 — superseded рішенням founder-а 2026-08-05: цільова пара після бети — LiqPay + «Плата» від Monobank; Stripe — неактивний задел, Paddle знято з активної послідовності; див. Update у шапці)_:

1. **Місяць 1–3 (MVP, UA):** обрати **LiqPay** — найшвидший старт, рідний для UA, знайома checkout-сторінка для Mono-юзерів.
2. **Місяць 3–6 (масштаб):** додати **Stripe** паралельно — міжнародні картки, Customer Portal, subscription lifecycle webhooks.
3. **Місяць 6+ (EN-ринок):** оцінити **Paddle** як MoR для автоматичного VAT.
4. **Нативні додатки:** Google Play Billing + Apple IAP обов'язкові для in-app purchases. Де можливо — redirect на PWA для оплати (маржа вища).

> **TL;DR:** старт з LiqPay → додати Stripe для масштабу → Paddle за потреби. Нативні сторінки — IAP обов'язково, але штовхати до PWA-оплати.

Технічна імплементація Stripe webhook + env vars → [03 §2: Що додати](./03-services-and-toolstack.md#2-що-додати-нові-сервіси). Week-by-week план → [03 §7](./03-services-and-toolstack.md#7-порядок-дій-week-by-week).

**Actual MVP contract:** Stripe Checkout session creation, subscription status read, Customer Portal session creation, and webhook idempotency are implemented server-side. Still pending: production Stripe account/env rollout, legal/tax readiness, remaining plan enforcement placements, billing settings polish, and LiqPay/native IAP follow-up.

### 6.1 Pricing UX (як показувати ціну)

- [ ] **Завжди показувати річну ціну першою** — ₴1490/рік виглядає дешевше ніж ₴199/міс.
- [ ] **Показати економію** — «Зеконом ₴898/рік з річним планом».
- [ ] **Показати вартість per-day** — «Менше ₴3/день — дешевше за каву».
- [ ] **Social proof** — «150+ людей вже на Pro» (навіть якщо це бета-юзери).
- [ ] **Money-back guarantee** — «30 днів гарантія повернення» — знижує бар'єр входу.

### 6.2 Paywall UI: upgrade invitation, не "стіна"

- Конкретна вигода, не абстракція: «AI-брифінг кожен ранок», а не «Pro features».
- Preview Pro-фіч (blur / skeleton) перед paywall — юзер бачить що втрачає.
- Кнопка «Не зараз» — не примушувати.
- Анімований sheet / bottom-drawer, не блокуючий popup.

### 6.3 Paywall placement: сценарії + UX wireframes

| Стратегія                      | Конверсія                     | UX                            |
| ------------------------------ | ----------------------------- | ----------------------------- |
| **Hard paywall** (одразу)      | Вища серед тих хто доходить   | Відлякує більшість            |
| **Soft paywall** (після value) | Нижча, але більше total users | Кращий UX                     |
| **Metered paywall** (ліміт)    | Середня                       | Юзер сам натикається на стіну |

**Рекомендація для Sergeant:** **Metered + Soft.** Free юзер отримує реальну цінність (всі 4 модулі базово), але натикається на ліміти (5 AI/день Free — ADR-0085, sync 2 devices). Paywall з'являється тільки коли юзер реально хоче Pro-фічу — це справедливо і не дратує.

## 9. Unit Economics: формули з цифрами

> Числа побудовані на таргетах з [04 §4: Метрики успіху](./04-launch-readiness.md#4-метрики-успіху). Актуалізувати після перших 3 місяців реальних даних.

### 9.1 LTV (Lifetime Value)

```
ARPU           = ₴199/міс (Pro monthly) або ₴124/міс (Pro annual)
Blended ARPU   = ₴199 × 0.4 + ₴124 × 0.6 = ₴154/міс
                 (гіпотеза: 40 % monthly, 60 % annual)

Avg lifetime   = 1 / monthly_churn
               = 1 / 0.05 = 20 місяців (при churn 5 %)
               = 1 / 0.08 = 12.5 місяців (при churn 8 %, песимістичний)

LTV (optimistic)  = ₴154 × 20 = ₴3 080 (~$70)
LTV (pessimistic) = ₴154 × 12.5 = ₴1 925 (~$43.75)
LTV (conservative, з 04) = ₴199 × 8 = ₴1 592 (~$36)
```

### 9.2 CAC (Customer Acquisition Cost)

```
Organic (SEO, DOU, Product Hunt, referral):   CAC ≈ ₴0–10
Paid (Facebook/Instagram, Google Ads UA):      CAC ≈ ₴40–80
Blended (70 % organic / 30 % paid):           CAC ≈ ₴20–35

Таргет з 04: CAC ₴20–40
```

### 9.3 LTV:CAC ratio

```
LTV (conservative) / CAC (blended max) = ₴1 592 / ₴40 = 39.8:1
LTV (optimistic)   / CAC (blended min) = ₴3 080 / ₴20 = 154:1

Діапазон: 20:1 → 80:1  (>3:1 = здорово, >5:1 = відмінно)
```

### 9.4 Breakeven

```
Фіксовані витрати:
  Hetzner CX23 (Coolify) ≈ $7/міс    = ₴308   (API+PG+Redis, ADR-0074)
  Anthropic API          ≈ $50/міс   = ₴2 200  (при 500 active AI users)
  Vercel (frontend)      ≈ $0        = ₴0      (free tier)
  Resend (email)         ≈ $0        = ₴0      (free tier до 3K/міс)
  Domain + Cloudflare    ≈ $2/міс    = ₴88
  PostHog (analytics)    ≈ $0        = ₴0      (free tier до 1M events/міс)
  ──────────────────────────────────────────
  Total fixed            ≈ $72/міс   = ₴3 168

Змінні витрати per Pro subscriber:
  Payment provider fee   ≈ 3 % × ₴199  = ₴5.97/міс
  AI API marginal cost   ≈ ₴5/міс     (більше запитів ніж Free)
  ──────────────────────────────────────────
  Total variable         ≈ ₴8/міс per Pro sub

Net revenue per Pro sub  = ₴199 − ₴8 = ₴191/міс

Breakeven subscribers    = ₴3 168 / ₴191 ≈ 17 Pro subscribers
```

> **Виправлено 2026-07-25:** тут стояло `₴3 168 / ₴91 ≈ 35`, хоча net per sub
> двома рядками вище — ₴191. Дільник не збігався з власним же числом.

> **Висновок:** з ~17 Pro-підписниками покриваємо фіксовані витрати — **за
> умови, що рядок «AI API marginal cost ≈ ₴5/міс» правдивий. Він не
> правдивий**: див. § 9.5 нижче. Детальна cost projection →
> [03 §9: Monthly Cost Projection](./03-services-and-toolstack.md#9-повна-monthly-cost-projection).

### 9.5 AI-COGS: оцінка з коду (2026-07-25)

> **Це ОЦІНКА, не вимір.** Виведена з прайс-таблиці й лімітів у коді, не з
> продакшн-телеметрії. Реальних даних немає: таблиця `ai_usage_daily` пише

**Префікс ВИМІРЯНО 2026-07-25** (не оцінено): 77 інструментів, 43 КБ JSON,
разом із `SYSTEM_PREFIX` — **14 400–21 200 токенів**. Докстрінг
`promptCache.ts` казав «~19 шт» і «~6000+ токенів»; це було занижено в

**Наслідок, який усе змінює: TTL prompt-cache = 5 хвилин.** Персональний
асистент використовується спорадично — люди не пишуть кожні п'ять хвилин.
Отже більшість повідомлень платить **cache WRITE, а не read**:

|                                  | Токенів | Ціна за Mtok               | Вартість     |
| -------------------------------- | ------- | -------------------------- | ------------ |
| cache **read** (тепле, <5 хв)    | 21k     | Haiku $0.10 + Sonnet $0.30 | **≈ $0.008** |
| cache **write** (холодне, >5 хв) | 21k     | Haiku $1.25 + Sonnet $3.75 | **≈ $0.106** |

Різниця — **більш ніж на порядок**. Плюс вихідні токени (до 1500 Haiku +
2500 Sonnet ≈ до $0.045).

> **Уточнення 2026-07-25 (пізніше того ж дня): 21k — верхня межа, і вона
> завищена.** У [`enable-prompt-caching.md`](../../../00-start/playbooks/enable-prompt-caching.md)

> `tools + SYSTEM_PREFIX`. Це справжній вимір токенайзера Anthropic, а не
> посимвольна оцінка, — і його в цьому розділі не врахували, бо він живе в
> іншому файлі. Реєстр тоді був меншим, точну кількість інструментів із
> історії репо не відновити (вона зрізана), але співвідношення дає **≈3.3
> байти/токен**: JSON-схеми переважають над кирилицею, тож payload ближчий
> до ASCII-краю, ніж припускала оцінка. За цим коефіцієнтом сьогоднішні
> 46 440 B ≈ **14 100 токенів** — тобто нижній край діапазону 14 400–21 200,
> а верхня половина діапазону надто песимістична. Таблиця вище, побудована
> на 21k, завищує вартість приблизно в 1.5 рази. Числа § 9.6 нижче вже
> перераховані на 3.3 B/токен.

**Одне повідомлення з інструментом:**

- тепле (в межах 5-хвилинного вікна) — **$0.01–0.05**
- **холодне — $0.09–0.15**, і саме воно типове

**Стеля, яку дозволяє код** (перерахована на холодних повідомленнях):

- **Free**, 5 одиниць/добу (зрізано з 15 у цьому ж PR): ≈ 1 виклик з
  інструментом або 5 простих → **$0.15/добу ≈ $4.5/міс**
- **Pro**, 20 premium + 80 standard: ≈ 6 + 26 викликів → **$1–3/добу ≈
  $30–90/міс**, плюс необмежений floor-хвіст

Проти виручки $4.6/міс: **Pro на стелі під водою в 6–20 разів**. Навіть при
20% використання квоти Pro ≈ $6–18/міс — тобто **все одно збитковий**.

**Головний висновок змінився після виміру.** Раніше здавалося, що проблема в
обсязі квоти. Насправді проблема в **розмірі префікса**: 77 інструментів на
кожному запиті — це $0.10 за холодне повідомлення ще до того, як модель
скаже перше слово. Зменшення кількості інструментів або їх опису дає більший
ефект, ніж будь-яке різання лімітів.

**Структурна інверсія — друга за важливістю.** Free і anon отримують **дорогу**

здогад — так написано в коді:

> `chat.ts`: «Free/Anon/founder/flag-off get the premium model =
> `CHAT_MODEL_SYNTHESIS` (unchanged behaviour)»
> `aiQuota.ts:592`: «Free/Anon/… → `premium`-модель»

Наслідок: кожен новий Free-юзер дорожчий за Pro на тій самій кількості
повідомлень. Єдиний важіль, що це згинає —
`ANTHROPIC_BUDGET_HARD_DEGRADE_ALL`, — за замовчуванням вимкнений.

   неоплаченому трафіку `standard`-тир замість `premium`. Kill-switch назад —
   `AI_FREE_ON_PREMIUM=true`. Аргумент, що зняв заперечення: Pro після 20
   викликів доби вже живе на standard, тож Free мав кращу модель за платника
   на його 21-му повідомленні; а перше враження формує reverse-trial на
   повному Pro (ADR-0068), не Free. Ціна — стенд глибини аналізу дає premium
   16/16 проти standard 13/16.

   **Уточнено того ж дня: деградація стосується ЛИШЕ чату.** Перша редакція
   зачепила й `coach-insight`, бо `resolveProTier` має два call-site, і це
   пройшло непоміченим. Там розрив `gpt-5.1` → `gemini-2.5-flash-lite` —
   найбільша втрата якості в усьому продукті за найменшу економію (~$0.0035 на
   виклик, ≈$0.05 на Free-юзера в місяць), а сам ендпоінт не має plan-gate, тож
   Free бачить його на дашборді щодня. Коуч повернуто на premium.

3. **Зрізати Free-квоту** — зроблено (15 → 5).
4. **Увімкнути `ANTHROPIC_BUDGET_HARD_DEGRADE_ALL`** як страховку на сплеск.
   **Не зроблено.**

**Чого ця оцінка досі не знає:**

1. Реальний розподіл «тепле/холодне». Я взяв «більшість холодних» із
   характеру продукту, а не з телеметрії. Якщо люди спілкуються серіями,
   числа падають у 3–5 разів.
2. Скільки повідомлень на добу шле реальний користувач. Вище — стеля.
3. Точний токенайзер Anthropic. Вимір зроблено посимвольно з розділенням
   ASCII/кирилиця і межами 3.2–4.0 та 1.4–2.4 симв./токен; `count_tokens`
   потребує API-ключа, якого в сесії не було. Похибка ±20%, порядок величини
   вона не змінює.
4. Курс ₴/$ у коді не зафіксований — узято ₴1 ≈ $0.023 з прози цього ж файлу.

### 9.6 Що зроблено з префіксом (2026-07-25)

Три важелі, реалізовані після виміру § 9.5. Числа — байти, поміряні тестом
`promptPrefixBudget.test.ts` (він же не дає їм тихо зрости назад).

| Важіль                                        | Було       | Стало            | Ефект                      |
| --------------------------------------------- | ---------- | ---------------- | -------------------------- |
| Контекстний префікс (tools + `SYSTEM_PREFIX`) | 46 440 B   | **7 564 B**      | **−84%**                   |
| TTL стабільного префікса                      | 5 хв       | **1 год**        | read замість write у сесії |
| Бюджет префікса                               | не існував | 9 000 B, CI-gate | не дає повернутись назад   |

**1. Tool search (`defer_loading`).** Усі 77 дефініцій далі йдуть у `tools[]`
(вони потрібні API server-side), але лише 5 «гарячих» потрапляють у контекстне
вікно. Решту модель знаходить через серверний `tool_search_tool_regex_20251119`,
і API дописує знайдені схеми інлайн — **префікс при цьому не змінюється, тож
prompt-cache виживає**. Саморобний per-module registry (те, що пропонував
попередній пункт 1) так не вміє: `tools` рендеряться на позиції 0, і будь-яка
зміна набору вбиває кеш цілком. Kill-switch: `CHAT_TOOL_SEARCH=false`.

Гарячий набір — `remember`, `recall_memory`, `morning_briefing`,
`get_daily_series`, `find_transaction` — це **гіпотеза**, а не вимір: прод-даних
про частоту викликів немає. Валідується по
`chat_tool_invocations_total{outcome="proposed"}`.

**2. TTL 1 година** на tools + `SYSTEM_PREFIX` (повідомлення лишились на 5 хв).
Write дорожчає 1.25× → 2×, read лишається 0.1×. Для N повідомлень у межах
години: 5 хв ≈ 1.25·N, 1 год = 2 + 0.1·(N−1); рівність при N ≈ 1.65 — тобто
вигода починається з другого повідомлення сесії.

**Перерахунок одного повідомлення.** Обидві колонки — за коефіцієнтом
3.3 B/токен зі smoke-виміру (див. уточнення в § 9.5), тож вони порівнянні
між собою: 46 440 B ≈ 14 100 токенів → 7 564 B ≈ **2 300 токенів**.

|                       | Було (14.1k, TTL 5 хв) | Стало (2.3k, TTL 1 год) |
| --------------------- | ---------------------- | ----------------------- |
| холодне (cache write) | ≈ $0.070               | **≈ $0.018**            |
| тепле (cache read)    | ≈ $0.0056              | **≈ $0.0009**           |

Холодне повідомлення подешевшало ~3.9×, тепле ~6×, і більшість повідомлень
у сесії тепер узагалі теплі (TTL 1 год). Проти виручки $4.6/міс Pro на стелі
все ще під водою — але вже приблизно в **1.5–4 рази**, а не в 6–20.

**Чого цей перерахунок не знає (нове, поверх списку § 9.5):**

1. **Вартість самого пошуку.** Знайдені схеми додаються в контекст як звичайні
   input-токени й **не кешуються** (вони йдуть після breakpoint-а). 3–5
   інструментів ≈ +1k токенів на ту розмову, де пошук стався. У числах вище це
   не враховано — вони описують префікс, а не повний запит.
2. **Кеш на Haiku, найімовірніше, зникне зовсім.** Мінімальний кешований
   префікс Haiku 4.5 — 4096 токенів, а новий префікс ~2.3k. Anthropic не віддає
   помилку, просто не створює запис (`cache_creation_input_tokens: 0`). Це не
   регресія (1× за 3k дешевше, ніж 1.25× за 21k), але cache-hit-ів на першому
   турі в метриках не буде — не лякайся.
3. **Точність tool-selection на 77 інструментах через пошук.** Anthropic
   стверджує, що вона зростає (їхній поріг деградації — 30–50 інструментів,
   у нас 77). Ми цього не перевіряли живим прогоном.
4. **Префікс усе ще пишеться двічі на повідомлення** — turn 1 (Haiku) і turn 2
   (Sonnet) кешуються окремо, бо кеш прив'язаний до моделі. Це закладено в
   числа вище, але як важіль не чіпалось.

**Третій важіль вийшов не тим, чим планувався.** Ідея була «підрізати описи
інструментів». Вимір показав, що з 42 906 B payload-у **27 323 B — це
українська проза** (описи інструментів і параметрів), а механічного сміття
(`additionalProperties`, `enum`) — менш ніж 700 B. Проза при цьому:
(а) після tool search уже не в префіксі, тож економія була б у ~1 КБ;
(б) є пошуковим індексом — `tool_search_tool_regex` матчить саме по іменах,
описах і назвах аргументів. Тобто скорочення описів псує рівно те, що ми
щойно ввімкнули. Замість косметичного різання зроблено **бюджет-гейт**
(`CONTEXT_PREFIX_BUDGET_BYTES = 9 000`): цифра в коментарі не ламається, коли
реальність від неї відходить, — а тест ламається. Саме тому попередня оцінка
й прожила стільки часу з «~19 інструментів».
